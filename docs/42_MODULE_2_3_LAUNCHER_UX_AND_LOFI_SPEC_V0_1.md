## 1. 目标

本文把模块 2、模块 3 和 EXE 启动器的业务规范转换成可评审的页面地图、操作流程、布局和状态。目标不是立即实现，而是先确定：

- 用户从哪里进入。
- 每个页面解决什么问题。
- 一屏中什么最重要。
- 主操作如何随步骤变化。
- 错误、取消、重试和恢复如何表达。
- 模块 1 资产如何无损进入模块 2。
- 模块 2 Release 如何准确进入模块 3。
- 启动器和 Web 工作台如何分工。

## 2. 设计原则

### 2.1 视觉属于 LI3D

继续使用现有 LI3D 的：

- 深蓝黑工作区。
- 粉紫主操作和选中态。
- 橙色空间辅助线、局部提醒和次级强调。
- 中央 3D 视口。
- 左右悬浮 Dock。
- 底部工具条。
- 细白边框、轻微辉光和 6 到 8 px 圆角。
- Noto Sans SC / Inter 与线性图标。

Marmoset、Substance、Fab/Bridge 和 Creative Cloud 只提供交互参考，不改变 LI3D 品牌。

### 2.2 一屏只解决一个主要问题

- 资产准备：确认输入是否齐全。
- 预检：确认能不能烘焙。
- 烘焙设置：确认生成什么和怎么生成。
- 执行：确认正在做什么、是否可取消。
- 检查：确认结果是否可用。
- 发布：确认正式资产包含什么。
- DCC 交付：确认发送到哪里以及结果是否正确。

### 2.3 主流程可跳过可选能力

ComfyUI、Normal、ORM 和 DCC 发送都不能阻断用户保存已经完成的必需结果。

### 2.4 默认参数简单，专业参数可追溯

普通用户先看到预设、地图选择和最关键参数。高级参数折叠，但提交 Job 时保存完整实际参数。

### 2.5 状态永远不靠猜

所有页面都显示：

- 当前步骤。
- 已完成内容。
- 缺失内容。
- 阻塞问题。
- 下一步动作。
- 文件和日志位置。

## 3. 全局信息架构

项目首页和编辑器增加一级模块入口：

```text
AI 纹理
PBR 烘焙
DCC 交付
```

推荐路由语义：

```text
/projects
/projects/:projectId/editor
/projects/:projectId/pbr
/projects/:projectId/pbr/jobs/:jobId
/projects/:projectId/pbr/releases/:releaseId
/projects/:projectId/dcc
/projects/:projectId/dcc/deliveries/:deliveryId
```

具体路径可在实现时调整，但 Module、Project、Job、Release、Delivery 必须可以深链接。

### 3.1 项目卡片

项目卡片增加轻量流程状态，不改变当前主视觉：

```text
AI 纹理：已保存
PBR：待准备 / 烘焙中 / 待检查 / 已发布
DCC：未发送 / 已发送 Blender / 部分失败
```

状态放在项目详情或悬浮信息中，不在卡片上堆满标签。

### 3.2 模块切换

编辑器顶部模块切换应明确区分一级模块与模块 1 内的 Scene/Texture/Normal 等模式。一级模块切换使用文字和图标；模块内部模式继续使用紧凑图标工具条。

## 4. 模块 2 工作区骨架

模块 2 复用现有 `EditorShell` 心智模型。

```text
┌─────────────────────────────────────────────────────────────────────────────┐

├──────────────┬──────────────────────────────────────┬───────────────────────┤
│ 流程与资产    │                                      │ 当前步骤检查器         │
│              │              3D 视口                  │                       │
│ 01 资产准备   │                                      │ 参数 / 问题 / 建议     │
│ 02 模型预检   │                                      │                       │

│ 05 PBR处理    │                                      │                       │

├──────────────┴──────────────────────────────────────┴───────────────────────┤
```

### 4.1 桌面区域

- 顶部浮动命令区：项目、模块、分辨率、环境摘要。
- 左 Dock：步骤轨道和资产角色。
- 中央：3D 视口或 2D 贴图检查。
- 右 Dock：当前步骤设置和问题详情。
- 底部：视口工具、上一步/下一步/开始烘焙/发布等主操作。
- 顶部中央临时进度条：沿用当前 Auto Bake Progress 的表达，但支持 Job ID 和分项进度。

## 5. 模块 2 页面/状态地图

### 5.1 M2-A 资产准备

目标：让用户确认模块 1 已交付什么，并添加低模和人工贴图。

左侧：

```text
高模              已接收
高模 BaseColor    已接收
低模              待添加
Cage              可选
Metallic          可选
Roughness         可选
```

中央：

- 高模默认可见。
- 拖入低模后显示高低模叠加。
- 角色使用不同但克制的轮廓色，高模粉紫、低模橙色、Cage 青色。
- 不使用大面积透明彩色填充遮挡模型。

右侧：

- 来源版本。
- 模型路径和哈希摘要。
- 单位、坐标、UV 和材质槽摘要。
- “添加/替换低模”。
- “添加人工 Metallic”。

底部主操作：`检查模型`。

空状态文案：

```text
已接收模块 1 的高模与 BaseColor
添加一份位置和比例一致、带 UV 的低模后即可检查。
```

### 5.2 M2-B 模型预检

目标：清楚区分阻塞、警告和通过项。

左侧步骤显示检查状态。中央默认高低模叠加，并提供：

- 高模。
- 低模。
- 叠加。
- UV。
- 包围盒。

右侧不使用一堆独立卡片，采用分组检查列表：

```text
阻塞问题 1
  低模没有可用 UV0
  [在 Blender 中修复] [重新选择]

警告 2
  高低模尺寸相差 3.2%
  低模尚未三角化

已通过 8
  文件可读
  包围盒相交
  材质槽可识别
```

点击问题时，中央视口定位或切换相关显示。

底部主操作：

- 有阻塞：`重新检查`。
- 无阻塞：`进入烘焙设置`。

### 5.3 M2-C 烘焙设置

目标：以少量决策完成任务配置。

左侧显示地图：

```text
BaseColor    必选
AO           必选
Normal       可选
```

右侧默认区：

- 烘焙器：Substance / Marmoset；切换只改变 Adapter，不改变源资产。
- 质量预设：快速检查 / 手工流程对齐 / 正式生产 / 自定义。
- 分辨率。
- Padding。
- 抗锯齿。
- Normal 方向，仅选择 Normal 时显示。
- 设备：GPU / CPU。
- 输出位置摘要。

高级折叠区：

- 前/后投射距离。
- 命中策略。
- UV Set。
- UDIM。
- Cage。
- 自动 Cage 膨胀与 Marmoset Offset 估算。
- Average Normals 等实现支持的参数。

中央视口：

- 低模为主。
- 可显示高模和投射包围范围。
- 调整投射距离时提供即时几何辅助预览，但不伪造最终 Bake 结果。

底部主操作：`开始烘焙`。

### 5.4 M2-D 烘焙执行

目标：稳定反馈长任务，不把用户锁死在模态框中。

左侧地图状态：

```text
BaseColor    已完成  00:48
AO           正在烘焙
Normal       排队中
```

中央：

- 已完成地图可以立即预览。
- 未完成地图使用明确等待态，不显示伪结果。
- 视口仍可旋转、缩放和切换已完成通道。

右侧：

- Job ID。
- 当前 Stage。
- GPU/CPU。
- 已用时间。
- 输出目录。
- 简化日志。
- `打开完整日志`。

底部：`取消任务` 为次级危险操作，不与主进度按钮混淆。

取消后保留已完成分项，显示：

```text
任务已取消
BaseColor 已完成并保留为候选，AO 与 Normal 未发布。
```

### 5.5 M2-E 烘焙结果检查

目标：以模型效果为主，日志为辅。

中央顶部通道条：

```text
PBR | BaseColor | AO | Normal | UV | 接缝
```

中央支持：

- 原高模 / 低模结果 A/B。
- 点击或拖动分割线对比。
- 问题标记。
- DirectX/OpenGL 预览切换。

右侧：

- 地图缩略列表。
- 自动验证结果。
- 接受、拒绝、标记重烘。
- 当前 Candidate 来源和参数。

底部主操作：

- `重烘选中地图`。
- `继续 PBR 处理`。

### 5.6 M2-F ComfyUI PBR 处理

目标：让非节点用户完成可选处理。

左侧选择任务：

- 净化 BaseColor。
- 生成 Roughness。

中央：

- 原始 / Comfy 结果分屏或滑杆对比。
- PBR 模型预览。
- 不展示节点图。

右侧：

- 工作流预设。
- 材质描述。
- 强度或保真度等少量已验证参数。
- Seed 和高级参数折叠。
- Comfy 服务状态。

底部操作：

- `跳过`。
- `开始处理`。
- 结果完成后 `使用原始版` / `使用处理版`。

### 5.7 M2-G PBR 检查与发布

目标：冻结一份可靠 Release。

中央默认 PBR 模型，并提供环境光/中性光切换。

左侧最终通道：

```text
BaseColor     已选择
AO            已选择
Normal        已选择 · DirectX
Roughness     已选择
Metallic      手工输入
ORM           未生成
```

右侧：

- Release 名称。
- 低模和贴图列表。
- 分辨率、色彩空间和方向。
- 警告确认。
- 输出目录。
- 版本说明。

底部主操作：`发布 PBR 版本`。

成功后显示明确摘要：

```text
PBR 版本已发布
release_...
1 个低模 · 5 张贴图 · 2 份报告
[进入 DCC 交付] [打开文件夹]
```

- 显示低模、PBR 缩略图、通道、Normal 方向和发布时间。
- Draft 或未完成 Candidate 不出现在默认列表。

### 7.2 M3-B 目标软件列表

### 7.3 M3-C 交付设置

- 模型格式。
- 单位和坐标。

- 材质模板。
- 目标工程或场景。

- 支持能力。

- 可以正常使用的模块。
- 暂不可用的可选能力。
- 阻塞模块 2 或模块 3 的问题。

## 9. 跨模块过渡

### 9.1 模块 1 -> 模块 2

模块 1 的导出区域新增 `进入 PBR 烘焙`，点击后：

1. 保存当前项目和模块 1 资产版本。
2. 检查高模和 BaseColor 是否可持久化。
3. 创建或恢复 PipelineAsset Draft。
4. 进入 M2-A。
5. 顶部显示来源版本，不要求用户重新选择高模。

### 9.2 模块 2 -> 模块 3

只有发布成功后显示 `进入 DCC 交付`。进入后默认选中刚发布的 Release。

### 9.3 返回

- 从模块 2 返回模块 1，不删除 Draft 和任务。
- 从模块 3 返回模块 2，默认打开对应 Release。
- 活动 Job 离开页面后继续由本地 Worker 执行。
- 顶部任务入口始终可以重新打开活动 Job。

## 10. 通用状态页面

### 10.1 Loading

使用结构骨架和真实状态文字，不使用长期全屏 Spinner。

### 10.2 Empty

说明已有内容、缺少内容和下一步。不要只写“暂无数据”。

### 10.3 Offline

区分：

- 本地 Backend 离线。
- Substance 不可用。
- ComfyUI 不可用但可跳过。
- DCC Connector 离线。

### 10.4 Error

显示稳定错误码、用户文案、出错步骤、是否保留结果和解决动作。

### 10.5 Recovery

重启后检测到活动 Job：

```text
正在恢复上一次任务
上次停留：等待 Blender 回执
[继续恢复] [查看日志]
```

## 12. 设计 Token 锁定方向

现有基线：

```text
背景            #0e1020 / #080914
面板            #151729 / 黑色高透明度
主色粉          #ff5ccf
主色紫          #8b5cf6
辅助紫          #6d5dfc
辅助橙          #ff9f43 / #ff8a68
主要文字        接近 #f7f4ff
边框            white 10% 到 30%
```

新增语义色应克制：

- Ready/Success：青绿色。
- Warning：橙黄。
- Error/Blocked：玫红偏红。
- Cancelled/Offline：中性灰。

禁止每个模块各自发明新的主色。

## 13. 响应式

模块 2、3 的主要生产目标是桌面 EXE 和桌面浏览器：

- 最小推荐宽度 1280。
- 1024 到 1279 时左右 Dock 改为抽屉。
- 小于 1024 只提供项目状态、任务查看、取消和日志，不承诺完整 3D 生产编辑体验。
- 触控不是 v0.1 的主输入方式。

## 14. 可访问性

- 所有状态同时提供文字、图标和颜色。
- 主操作有明确焦点态。
- 步骤轨道可键盘导航。
- 进度变化使用克制的 `aria-live`。
- 日志区域不抢夺焦点。
- Tooltip 不作为唯一信息来源。
- 危险取消操作提供结果说明，不使用浏览器原生 confirm。

### 17.1 模块 2：PBR 烘焙工作台

- 文件：`docs/design/concepts/module-2-pbr-bake-workspace-v0.1.png`。
- 场景：项目已进入模块 2，资产角色已绑定，预检通过，用户正在确认烘焙参数。
- 评审重点：左侧步骤与资产、中间 3D 检查、右侧参数、底部任务动作之间的主次关系。
- 当前判断：可以清楚表达“准备资产 → 预检 → 烘焙 → 检查 → 发布”的主线；专家参数被收在右侧，不阻断新用户。

### 17.2 模块 3：DCC 交付中心

- 文件：`docs/design/concepts/module-3-dcc-delivery-v0.1.png`。
- 场景：一个 Release 已准备完成，Blender 连接器在线，用户准备发送。
- 评审重点：Release、目标 DCC、转换规则、连接状态、任务队列和回执是否形成清楚关系。
- 当前判断：采用“左侧目标/历史 + 中间交付配置 + 右侧连接器 + 底部任务队列”，适合多 DCC 扩展，也避免让发送动作变成不可追踪的一键黑盒。

### 17.3 启动器：连接器与运行环境

- 文件：`docs/design/concepts/launcher-connectors-v0.1.png`。
- 场景：运行服务已经就绪，用户检查 Blender、3ds Max、Maya、Photoshop 和 Substance 的连接状态。
- 评审重点：启动器是否只承担运行环境、连接器安装/修复、诊断和进入工作台，而不复制 Web 的生产界面。
- 当前判断：沿用现有启动器的信息密度和状态侧栏，把现有 Photoshop 专属连接能力自然升级为通用 Connector 管理。
