## 2. 架构边界证明

- `check:cloud-boundary` 校验仓库不存在 Li3D 本地组件、loopback bridge、桌面中介或旧 ComfyUI 状态接口依赖。
- `check:cloud-artifact` 校验发布制品只包含 Web 与服务端运行所需内容；候选制品共 184 个文件、约 24.83 MiB。
- `/li3d/api/comfyui/status` 在 A100 返回 `404`，证明旧本地组件探活入口未被带回。
- 工具箱下载属于可选建模工具包，不是 Li3D 主流程运行依赖。
- Feishu 登录走服务端 Web OAuth 回调与 HttpOnly 会话 Cookie，不依赖 Atlas CLI。

## 3. 同事版本能力迁移

已迁移并保留的关键能力包括：

- 原版首页、登录页、项目列表、编辑器、工具箱和新版品牌资源；
- 模型与参考图上传、多视角/单视角生成、局部重绘及结果图层；
- 贴图投影、遮罩语义、边缘融合和批量烘焙相关算法修复；
- UV、拓扑与烘焙云端任务及账号级任务历史；
- 账号、项目、资产和任务历史隔离；
- 409 项目版本冲突的自动恢复、幂等提交和前端并发锁；
- 多设备访问时统一使用服务端生成服务凭据，避免只在部署者电脑可用。

迁移只吸收功能与缺陷修复，不恢复旧本地组件架构。

## 4. 自动化验证范围

本地与 GitLab 使用同一组发布门禁：

1. 云端边界与项目仓储边界检查；
2. 协议契约测试与 TypeScript 类型检查；
3. Web 回归测试（62 项契约）；
4. Server 回归测试（8 项契约）；
5. ESLint；
6. Release 构建、云端制品检查、Web 包体预算；
7. 模拟云端部署与健康检查。

回归覆盖生成任务冲突恢复、登录弹窗与 OAuth、生成轮询、项目新手引导、工具箱、真实 UV 交接、PBR 烘焙、100 账号隔离、多副本和 PostgreSQL 稳定性场景。

## 5. A100 运行验收

- `/li3d/api/health`、`/li3d/api/ready`、`/li3d/api/release` 均返回 `200`；
- `runtimeMode` 为 `cloud`，发布接口返回上述完整 Git SHA；
- systemd 服务为 `active`，重启次数为 `0`，部署后日志无持续错误；
- 旧 dist 与临时 stage 目录已经清理，当前服务只指向已验收发布制品。

## 6. 仍需人工业务验收的项目

自动化与 A100 健康检查已经通过，但正式上线前仍应由非部署者设备完成一次真实业务点击验收：登录、上传隔离测试模型和参考图、提交生成、等待产物、打开结果图层、退出后重新登录并确认账号历史。该步骤用于验证外部生成服务、网络和真实账号权限，不以 Mock 结果代替。

## 7. 合入 main 的规则

- 只有候选分支最新 GitLab 流水线全部通过，且本地完整门禁再次通过，才允许合入 `main`。
- 使用普通 merge commit 保留 `main` 历史，不 force push，不修改 `master`。
- 合并后的 `main` 流水线仍须通过；失败时使用普通 `revert` 或回滚到上一份已验收制品。
- 运行配置、数据库和账号资产不随代码回滚覆盖。
