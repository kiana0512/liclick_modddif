# 透视/正交切换保持当前取景

- 入口：UI-07 视口投影按钮 → M03 场景、相机与捕获。
- 算法：`ALG-VIEW-PROJECTION-001` / Projection framing continuity / 投影切换取景连续性，v1.0.0。
- 状态：生产路径修复，本地验证，尚未推送或部署。实施：Codex；真实工程体验验收：维护者。
- 触发证据：用户录屏 `20260921163612_rec_.mp4`；切换后模型画面剧烈变化。原控制器销毁旧相机，初始化位置及正交 zoom=90，并因相机 UUID/模型集合重置重新 fit；残留的 restore 请求也随相机重新执行。

## 输入与输出

输入为旧 Three 相机、当前轨道中心以及新投影相机/视口尺寸，使用世界坐标长度、垂直视场角和无单位 zoom；无颜色空间变更。以轨道中心所在的相机平面为基准，透视可见高度 `H=2*d*tan(effectiveFOV/2)`，正交高度 `H=(top-bottom)/zoom`。透视转正交使用 `zoom=(top-bottom)/H`；反向由 H 和新相机有效 FOV 解出距离。

保留轨道中心、观察方向和 up（含越极旋转），继承裁剪范围并沿既有自由导航裁剪规则扩展。透视的近大远小与正交投影固有差异保留，不承诺不同深度所有顶点屏幕位置完全相同。

相机交接在 layout effect 中完成；自动取景身份只依赖工作区/对象，不再依赖相机 UUID。初始导入、显式选中聚焦与工作区切换策略不变。恢复请求只在匹配投影类型时应用一次，不因之后的手动投影切换重放；后续新的显式恢复仍生效。

## 对应路径与兼容

CPU 相机矩阵在单独 viewport 算法模块换算。GPU 继续消费当前视口矩阵；冻结的 Capture/projector、GPU/CPU/Worker/shader 纹理重投影、UV/蒙版、历史图层及模型导出算法不变。没有新的 Layer 或资产输出；Project/Camera Schema、Command、CAS、ownership、QA 和最终贴图分辨率不变。旧项目无需迁移。

回滚本次控制器与 helper 即恢复原切换行为，不删除或改写项目和资产。只需更新前端，不需要数据库或计算服务迁移。

## 验证

- 数值回归：27 组视口比例/观察距离/非单位透视 zoom，每组 20 次往返；轨道平面屏幕坐标误差 <1e-9。含平移、越极 up、正交缩放和裁剪范围。
- Edge 真实 WebGL + React StrictMode 挂载正式 CameraController：16 次切换保持中心/方向/比例；验证正交缩放、resize、旧恢复不重放和同时切模式的新显式恢复。
- 同一浏览器用 `CAMERA_PROJECTION_BASELINE=6067cf22` 加载旧控制器，第一次切换报 `target jumped`；新控制器通过。
- 模型放置/相机聚焦、选择驻留、ViewCube、滚轮/导航、多模型恢复、模型导入、FBX 修复、捕获隔离和法线捕获回归通过；Web typecheck、改动文件 lint、构建和 diff 检查通过。
- 普通本地构建的既有包体与 256-byte 余量检查通过：总 JS 3,256,212 / 3,256,500 bytes，余量 288 bytes，未提高预算。该构建不是带完整 CI 身份的发布构建，推送前仍须针对最终提交运行 `verify:prepush`。
- 未连接或修改真实用户工程，未部署；不以隔离测试宣称用户原模型已完成线上验收。
