# 采集回读分段与法线预览独立离屏

## 预设快速切换修正（CAPTURE-NORMAL-ISOLATION/1.1.0）

主模块 M03，协作 M04/M06/M08。离屏副本不能等待未来挂载的模型：改为在真实场景确认目标就绪后才复制。预览请求携带 AbortSignal，在队列入口、交互等待、模型挂载等待以及实际法线绘制前检查取消；已经提交的 GPU 回读仍排空后释放。预设切换等待 180ms 再启动缺失视角，重复点当前预设不启动工作；同模型保留已完成视角缩略图，模型切换仍清空。缓存只用于现有 512px UI 缩略图，正式生图仍重新按请求原尺寸采集，不降低分辨率、不跳过拟合或 QA。

验证：1,000 个排队后立即取消的请求全部以 AbortError 结束，零就绪检查、零复制/绘制；晚挂载模型在复制前加入真实场景，副本能找到它。冻结相机的 1K/2K/4K 法线引导回归通过。驱动替身测试不等同于真实按钮 FPS 验收，真实页面仍需复测。

4517 内置浏览器实测（1280×720，测试合集 cooler）：初始 10 张预览完成，切到预设 2 后 14 张完整 512px 预览，随后 10 次交替切换预设 1/2、切到自定义 6 张、再回到预设 2。该轮人工录制 60.0 FPS、P95 16.8ms、峰值 18ms、丢帧 0；最后长任务仍为初始模型贴图上传，不是此次切换新增。修复后无新的 ImageUtils.getDataURL 警告；历史日志保留的同名警告来自修复前旧包。初始工程恢复仍有长帧，此结果不代表所有交互或冷启动已无卡顿。法线材质同一次 pass 共用一个实例，结束释放；SkeletonUtils 只按名引入 clone，避免捆绑未使用重定向动画工具。

真实 4517 控制台发现每轮采集连续触发 THREE.ImageUtils.getDataURL，将运行时贴图同步编码为 JPG。原因是 Object3D.copy 对 userData 的 JSON 序列化，触发其中 Texture.toJSON。修正为逐节点复制独立状态，复制时以只读代理提供空 userData，再创建浅层元数据字典；嵌套资源只读共享，骨骼继续由 SkeletonUtils 建立独立映射。采集模块审计未发现写入嵌套 userData；测试使用会抛错的 toJSON 哨兵，证明复制不触发资源序列化，原材质、骨骼和目标标记均保持。

ALG-CAP-007/1.1.2 对索引几何的重复顶点仅计算一次位置和相机约束，保留索引绘制范围、两百万提交索引上限、4ms 协作等待、形变后备和完整轮廓 QA；最多临时 2MB 标记。取消信号继续传入拟合及轮廓检查。72 组相机回归通过，六个索引只读取四个实际顶点的断言通过，未使用的顶点不参与拟合；不改变产物语义，无数据迁移，回滚去重标记恢复逐索引计算即可。

GPU/CPU/Worker/shader 数学与编码不变；持久化、导出、Command/CAS/ownership 无变更，无数据迁移。回滚此版本的 signal、就绪前置、预设缓存复用及延时调度即可，保留原离屏隔离。

- 问题：颜色/蒙版/法线等采集仍一次回读整张图，异步 API 结束时的驱动拷贝会同步占用主线程。初始多视角法线预览还共用可见渲染器和场景临时材质，需排除正常视口被采集状态干扰。
- 实现：复用 1 MiB 分段回读，增加矩形高度支持，唯一最终缓冲、完整像素和行序保持。所有在途回读排空后才释放目标；可见渲染器保留绘制边界，独立上下文最多八条并发。
- 离屏：法线缩略图及正式几何法线引导在独立 WebGLRenderer 和场景副本执行；材质/可见性只改副本，骨骼也独立，原几何数组只读共享。相机拟合与轮廓检查也使用副本；渲染任务串行、交互结束后开始，空闲 20 秒释放额外上下文及其 GPU 资源。存在额外一份几何 GPU 上传和上下文开销，未声称零显存成本。创建失败明确报错，不悄悄回退修改可见场景。
- 验证：方形与 2048×1537、1537×2048、4096×512 矩形完整字节及尾条带对照；真实采集函数的绘制边界、材质/背景/FBO 状态恢复和失败清理通过。实际 Three 场景/骨骼克隆验证原模型材质、可见性不变；串行所有权、失败后可再执行及空闲释放通过。驱动替身用于确定性回归，不冒充用户页面 FPS 或实际离屏像素对照。
- 审计：原捕获尺寸、色彩输出、相机/mask/depth、引导图及 PNG Worker 保持；GPU/CPU/Worker/shader 数学、正式 UV/回贴、QA、Command/CAS/ownership、持久化和导出协议不改，无 Schema/资产迁移。回滚离屏包装和矩形回读调用即可，原成功资产保留。
