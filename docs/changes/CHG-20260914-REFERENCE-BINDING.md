# 最新多视图替换与绑定

- 主模块 M04，协作 M08；UI-05；`REFERENCE-GROUP-BINDING/1.1.0`。
- 用户要求：重新生成多视图后替换该来源单视图的旧多视图，并在后续上材质时使用新图。

## 原因与修复

原写回操作会移除同组旧图，但后台恢复逐个寻找“成功且不在参考列表”的历史任务；刷新后的防重复集合为空，旧任务因此又被认定为待恢复，把新图替换回旧图。此外，保存使用的是选择更新前的 references 快照，新图的 isPrimary=false 被写入工程。

现在按项目和 sourceReferenceId 归并任务，使用 startedAt 选择最新发起者；完成时间、查询顺序不决定新旧。同时间或缺失时间使用任务 ID 稳定决胜，不声称能还原缺少时间的历史先后。恢复仅处理最新任务的成功结果；较新任务运行/失败时，不复活更旧任务。已有旧绑定在新图成功前保留。

新图持久化为 verified reference asset 后，写回前再次检查当前项目、来源存在、任务仍为最新。确认后删除同组或同 derivedFromReferenceId 的旧多视图，写入新图，并把来源单视图显式归入该组；只将新图标记为 isPrimary，UI 与工程保存共用同一快照。其它组的图片、历史生成记录和对象资产不删除。单视图、多视图纹理生成与局部重绘继续通过已有分组解析器获得新绑定。

成功写回的 Generation.metadata.referenceBindingApplied=true 随既有项目保存；缺省为未写回。该标志避免已应用结果被用户删除后又从任务历史复活。旧项目中仍保存新旧成功任务和提交时间时，可恢复最新结果，修复旧代码造成的绑定回退。

## 验证与兼容

`test:reference-binding` 执行真实面板恢复条件、写回函数与分组算法，覆盖替换、来源关系、选中状态持久化、旧历史在前、刷新恢复、删除后不复活、新任务失败/运行、旧任务迟到、跨项目、来源删除、持久化期间切项目及旧错误分组清理。上材质参考解析专项继续验证选中来源单图时得到新多视图。

为保留新增校验并遵守现有包体预算，将面板 14 处完全相同的元数据字符串判断复用为 generationMetadataString，仍保留空字符串/空白，非字符串仍返回 undefined；任务身份私有 metadataId 继续把空字符串视为缺失。分组字段只在最终写回时构造一次。没有提高预算、删除诊断或降低质量。使用 Cloud、性能实验室开关和完整发布元数据的构建：93 个 JS chunk，共 3,226,493 / 3,226,500 字节；shell 258,247、editor 490,121、bake 697,524、shared 828,983 字节，各门禁通过。源码尚未提交，正式推送前仍需对最终提交执行 verify:prepush。

类型检查、lint、Web 125 项完整回归、最新写回专项及 Cloud artifact 检查通过。新增图片上传失败用例确认不修改现有绑定。本次使用受控持久化夹具，不提交付费生图，不声称已验证用户线上工程的实际图片输出。
