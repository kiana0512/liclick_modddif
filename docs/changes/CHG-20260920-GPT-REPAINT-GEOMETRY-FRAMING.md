# GPT 局部重绘轮廓来源修复

- 主模块 M04，协作 M03/M08/M12；基线 `5c155f73`，本地实现，未发布。
- 算法 `GPT-REPAINT-GEOMETRY-FRAMING/1.0.0`、`GPT-CONTENT-BOUNDS/1.1.0`；production 路径。

## 原因与行为

法线背景开关使法线图的黑色/蓝色背景也不透明。旧局部重绘取景以法线 alpha 识别主体，因此错误地将整个画布保存为 framing.subject；远端返回正常透明背景时，被严格轮廓校验误拒绝。回归先在旧实现复现了全画布边界与真实模型边界不一致。

新局部重绘直接读取提交前已冻结、已保存的同相机 `linear-view` RGB packed depth。沿用模型轮廓裁剪的白色 clear 判定：alpha 非零且任一 RGB 通道小于 254 才是模型覆盖；不按法线颜色或材质颜色猜测轮廓。逐行两侧扫描保留合作调度与取消，得到完整模型边界，按既有长边 1:1 取景同时裁切主图和法线。局部重绘 maskUrl 是作者选区，不作为模型轮廓。缺深度、编码不符、尺寸不符或空覆盖均在付费请求前阻断。

## 路径审计与边界

- GPU/capture/shader：复用既有深度 pass，无新增渲染；法线、主图、作者 mask 像素不改写。
- CPU：仅增加 packed-depth 覆盖扫描模式；旧布尔模式保持原行为。输入/输出坐标仍是原截图像素，framing v2 与反变换不变。
- 返图 QA：保留原生分辨率、比例校验及严格 `max(16px, 长边×2%)` 外边界误差上限，真实平移/缩放仍拒绝。这是外边界检查，不承诺检测内部零件或语义形变；无法提取可靠透明轮廓的全不透明返图仍拒绝。
- Worker/回贴/UV/export：继续使用原作者选区、冻结相机和深度，保持既有 gpt-source-alpha-v1 合成，不扩大可编辑范围、不侵蚀原始返图 alpha；无新 GPU/CPU 双实现。
- 持久化：修正后的 subject 使用已有 framing 字段随任务保存；即时、轮询、历史恢复均消费同一数据，不依赖当时视口。Project Schema、Command/CAS、ownership、verified assets 不变。
- 迁移：不重写旧任务及资产。已失败任务仍保留原取景元数据，需要重新生成。回滚两处引擎修改即可恢复旧来源；已生成结果仍兼容现有协议。
