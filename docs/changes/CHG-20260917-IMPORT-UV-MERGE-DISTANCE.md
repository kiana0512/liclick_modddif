# 展 UV 前按距离合并顶点

主模块 M02，协作 M10/M13；IMPORT-UV-REPAIR v1.3.0。用户截图要求添加 Blender“合并顶点 → 按距离”，在智能 UV 投射之前执行。

## 行为

- 异常 UV 确认后，服务器 Blender 对每个对象独立进入编辑模式、全选，调用 `bpy.ops.mesh.remove_doubles(threshold=0.0001, use_unselected=False)`。距离为对象本地坐标单位，不应用对象缩放，不跨对象合并。
- 实际合并返回资产中的顶点，不仅更改临时 UV 工作网格。确认框同步说明网格连接和 UV 布局会改变。无需额外第三个弹窗；拒绝既有 UV 确认则不上传、不合并、不导入。
- 合并后的几何进入原智能 UV 投射（66°）→ 平均岛尺度 → 0.001 排布边距 → 按需补足 1e-6 外边界流程。仅需减面且 UV 合格的模型不额外展 UV 或执行此合并步骤。
- 保留材质分区及 Blender 支持的数据；合并会改变局部连接、顶点数，可能删除退化或重复面，不继续宣称原几何/面角法线逐位保持。UV 投射不再改变合并后的三角面数。

## 校验、对应路径、迁移与回滚

- 合并后、UV 后及导出回读按对象检查非空表面、有限坐标、对象数量以及原始表面积比例 [0.99,1.01]。严重变化拒绝输出，不放宽 UV QA 作为补救。面积保护不等于完整形状误差或微结构保留证明。
- 0–1、有限 UV、非零三角形 UV 面积与合并后/导出回读三角面一致性继续检查。原文件不覆盖，全部通过后才返回/注册/保存最终 GLB；保留源单位。
- CPU/GPU/Worker/shader 使用最终同一模型，无独立合并副本或像素计算变化；投影/绘制/UV合成/export 内核及分辨率不变。Project Schema、Command/CAS、ownership 和 verified assets 不变。无存量工程迁移，历史资产不自动重处理。
- 回滚到 v1.2.0 的 UV 脚本及确认文案，保留已生成资产。若需恢复原顶点，必须重新导入源文件；回滚代码不能恢复已经合并的网格。

## 验证

- `apps/server/scripts/test-import-uv-merge-distance.py` 在实际 Blender 5.1.2 执行生产脚本：两个重合但独立对象，每对象两组三角面端点相差 0.00005；合并 4 个顶点，保留 4 个三角面、2 个对象、两种材质分区，返回 UV 无越界/退化。
- 小于合并距离的独立三角片被表面校验拒绝，未导出结果。
- 既有服务端方法/格式/独立 consent、浏览器阈值/取消/二次 UV 确认/文件重开测试、Web 类型检查、确认组件 lint 均通过。
- 实际机械模型（原 400162 三角面）经本轮生产 HTTP handler + Blender 完成合并、智能投射、排布/内缩及 GLB 回读 QA，输出 21,524,916 字节；完成后客户端断连/共享处理槽释放回归通过。测试在隔离临时目录运行，不修改用户项目。
- 另一个旧火车样本在 v1.2.0 和 v1.3.0 都被退化 UV 校验拒绝；不宣称此次合并能修复所有几何问题，不降低原 QA 让其通过。
- 不替换线上应用；本地完成后等待用户发布指令。
