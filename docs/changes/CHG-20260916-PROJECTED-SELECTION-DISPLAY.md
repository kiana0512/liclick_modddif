# PROJECTED-SELECTION-DISPLAY/1.0.0 — 编辑器投影选区显示

主模块 M08，协作 M03，入口 UI-06。正式 ViewportCanvas 使用独立投影显示内核；不是四槽原型页面。模型 UV 不参与新绘制选区的红条纹显示，作者 UV 蒙版仍沿用原累积、捕获和远端输入链路。

## 算法与生命周期

冻结相机、屏幕笔画和深度，GPU RGBA8 数组纹理保存 RGB24 深度与 A8 覆盖；按序添加/擦除，最后反选。接收平面深度校正、前后面门禁和原深度偏移保留。同相机同操作相邻归档合批，不在鼠标移动时读回。保持原 450ms 空闲 UV 归档时机；撤销历史额外保留待归档屏幕 Canvas 和冻结相机，仅撤销/重做时重建深度，不强迫每次抬笔烘焙 UV。

GPU 显示缓存最多 192 个 512×512 层（常驻 192MiB，另有 1MiB staging；最后一次扩容短暂同时持有旧 128MiB 和新 192MiB）。初始仅 4 层；随历史根回收槽位，模型释放时 dispose。历史沿用 80 步上限，待归档屏幕快照每份最多约 1MiB；before/after 可能各持有一份。视角记录受显卡 uniform 限制，最多 128；达到限制或 GPU 失败明确提示回退原 UV 显示，不丢弃实际选区。旧 UV-only 状态及原生重绘消耗选区后也使用原 UV 显示，清空后可恢复投影显示。因此不承诺历史恢复或消耗后的选区始终无 UV 缝。

## 一致性审计

GPU：仅新增显示缓存和材质；原作者 UV 累积核不变。CPU：新增会话内待归档笔画历史，保留未归档笔画的撤销语义。Worker 不变。Shader 不采样模型 UV，保留遮挡检查。辅助覆盖层沿用 capture 排除标签。保存、远端提交、回贴、UV/export、完整输出分辨率和 QA 不变；无数据库、Schema、资产迁移，Command/CAS/ownership 不变。

## 验证

实际 ViewportCanvas、本地隔离项目、用户车辆 1,999,546 三角形，RTX 4070 Ti，1280×960、DPR 1：连续涂画及七个投影视角旋转帧间隔 P95 16.8ms（约 60FPS），没有 >50ms 主线程长任务；首次笔画输入至下一 RAF 最大约 23.4ms。此为本机测试，不代表所有客户端硬件，也不是 A100 GPU 生图速度。停笔 1 秒后确认累计纯投影显示已启用，非只验证实时笔画。

模型 UV 全部置零再恢复，离屏显示 RGBA 完全一致；擦除、撤销/重做、反选、清空及撤销清空通过，作者蒙版 decoded RGBA 摘要一致；超过四视角保留。独立内核测试覆盖 GPU 异常回退、历史槽位、对象变换及释放。没有发起付费生图。真实编辑器视口截图和指标由 run-projected-selection-editor.mjs 生成。

## 发布与回滚

显示内核独立构建为 projected-selection-display chunk，与烘焙入口分离缓存；manual chunk 仅包含明确指定模块，不吸入共享 Three 依赖。总 JS 与既有逐块预算保持，不靠提高上限通过。

发布前在最新 master 上执行正式 prepush 门禁，保持原包体限制。仅替换 Li3D 应用产物，保留配置、运行时资产和旧产物备份，不修改 A100 其他服务。回滚本提交及配套会话历史字段即可恢复原 UV 显示；无需迁移数据。生产版本与发布验证以部署结果为准。
