# 大模型 UV 接缝缓存

2026-09-15。主模块 M07；协作 M06、M09。算法 `ALG-UV-005` Topology-constrained postprocess / 拓扑约束后处理 v2.0.7（实现 Patch，像素语义不变）。维护责任 M07。

## 原因

本地“新项目1”、2K 最近完成记录：总流程 3547.0ms，其中接缝 2654.7ms。几何快照 108000000 字节，超过 32 MiB 的快照上限；修补方案未缓存，重复显隐会重新遍历模型并构建接缝关系。拓扑准备也调用同一个快照工具；异步准备计时与接缝交错，不可把各计时全部相加。

## 实现与契约

- `uvSeamGeometrySnapshot.ts`：不超过 32 MiB 的小源沿用原始字节快照；大源用现有 fflate 在 65536 字节块内做无损 DEFLATE level 1。比较时解压并检查全部原始字节，不使用短哈希或 needsUpdate 代替内容判断，NaN/signed-zero、浮点/整数原始位及尾部字节均保留。
- 缺失覆盖修补的快照与地址共享原 64 MiB 地址预算：以前最多为 32 MiB 快照加 64 MiB 地址，现在两者合计最多 64 MiB。按实际压缩字节扣减地址容量，并向下取整到完整地址块，避免末块分配超限。通用接缝对象缓存及拓扑专用快照仍使用原 32 MiB 单项上限。压缩或地址超限放弃缓存，继续原精确构建。单次比较只解压一个 64 KiB 块，不还原整份 108 MB 副本。缓存元数据为少量分块描述，不以总进程 RSS 即时下降作为保证。
- 每块返回协作调度器，原 8ms 让出/取消门禁继续生效；复用前仍验证模型结构、属性类型/范围、变换及所有源字节。拓扑专用模式保持只检查 UV/index 的原范围。
- `uvSeamReconciliation.ts`：缺失覆盖修补只创建一份快照，由最终修补地址方案统一验证和持有；移除该路径重复压缩、重复验证和中间接缝对象缓存登记。平均接缝路径继续使用原接缝对象缓存。
- 复用完整原顺序地址（包括重复地址），仍逐次读取当前 RGBA/coverage，并允许前一修补成为后续来源；取样、bandPixels、Alpha、0.55 法线阈值和位置/UV 量化不变。最终修补缓存不再保留第二份中间接缝对象缓存。
- 增加页面诊断 `residentUvSeamSnapshotBytes` / `residentUvSeamSnapshotEncoding`；缓存命中同时刷新方案存在与地址数量，避免诊断保留别轮旧值。
