# CHG-20260910-ADAPTIVE-GAP-DISTANCE

## 范围与证据

主模块 M07，协作 M05/M06/M08；LOCAL-BOUNDARY-REPAIR v1.1.0；维护文档 2.20.6。保留上一项未发布的 REPAINT-MERGE-ALPHA 修复。

用户录像显示嘴内部仍有较大斜线区域。v1.0 在 2K 将距离限制为 16 texel，算法回归复现宽缺口中间无法覆盖；仅凭录像不能确认用户嘴内是否另有完全无纹理的 UV 岛，本次不承诺修复无有效边界的区域。

## 算法

新增可选 adaptiveGapDistance，必须同时启用 localBoundaryBlend 才生效。生产策略开启，旧显式调用缺省关闭；maxDistance=0 仍完全禁用传播。以原 8/16/32/64（1K–8K）为初始半径，当前 BFS 到达半径且队列仍有前沿时倍增距离上限，最多 pixelCount；队列耗尽自动停止。stats.maxDistance 表示实际扩展后的上限，maxDistanceReached 表示实际走过距离，不用扩大图像或降分辨率。

自适应模式只从与 writeMask 相邻的可靠原始颜色起步，只穿过 writeMask 内、topologyMask 内、同 topologyRegionIds 的像素；未选的弱透明区不能作为桥梁。owner 始终指向本次输入的有效源索引，每个缺口像素只入队一次，不把新合成图反复作为来源运行。随后继续既有 8–64 次局部颜色过渡、强色差隔离、窄裙边与透明 RGB bleed。无额外整幅缓存/重新扫描，也不改变微小噪点过滤。

无来源组件继续保留，不恢复全局平均色、不跨 UV 岛猜颜色。非静默手动操作仍有 unresolvedPixels 时使用 warning，并显示剩余像素和局部重绘建议。该算法是颜色延展，不识别嘴部语义，也不生成缺失细节；历史修补若已在输入中，仍被视为现有内容，不自动删除或重着色。

## 对称审计

- CPU / Worker 传同一标志，执行同一 BFS/混色函数；复用队列，传播 O(N)，不新增 atlas 数组。进度按访问数节流，避免细长缺口逐层发海量消息；保留取消。
- GPU / shader / 拓扑捕获和投影不变。预览、颜色贴图、合并 UV、FBX 继续消费同一个稀疏修补 underlay，改变的是新修补覆盖范围，不改变导出合成公式。
- 无 Schema、Command、Revision CAS、ownership、verified assets 变化，无旧数据迁移/历史清空。
- 不改变输出分辨率、图像加载策略或质量门禁。新增代码 Cloud 总量实测从 3162508 到 3163384（+876 字节）；仅增加 1000 字节功能预算，单 chunk 预算不动，发布元数据仍需再验证。

## 验证

- Web 109 项完整回归、Cloud 生产构建、修改范围 ESLint、产物边界和包预算检查通过；与前项 UV 合并透明度修复共同验证。
- 26 项内容修补测试：窄缝渐变、宽 255px 缺口原来仅填 32px 现在填满；原始 donor 数仍为 2；绕弯缺口按图距离补全、孔洞/跨区域/未选弱区域隔离、无来源不填、固定距离兼容、禁用/取消和进度不倒退。
- 真实 Edge 2048×2048、128px 宽缺口：修补 262144px、最大实际传播 64px；独立无来源区 301056px 保留；globalFallbackPixels=0；Worker 与主线程字节差异 0，PNG 中心 RGB=[140,80,95]。合成样例 main 730ms / Worker 785ms（含启动和复制），不代表用户模型耗时。
- 未取得录像对应完整模型/图层/拓扑数据，仍需原工程验收；完全无参考色的独立区域应局部重绘。

## 发布与回滚

用户确认与前项 UV 合并透明度修复一起提交 master 并部署 A100。发布使用带 Git SHA 的 Cloud 产物，备份三处 dist 和版本元数据，保持 runtime/非版本配置，失败回滚。旧有限补缝可以保留为输入继续补缺口；若希望完全重新计算，先通过原历史撤销修补再运行。算法回滚时关闭生产 adaptiveGapDistance 或恢复本次代码即可，已有生成的修补资产仍可显示、导出，不删除它们。
