2026-09-21，M08 性能诊断；未修改工作流、模型、步数、输入分辨率、ComfyUI 或个人服务运行代码。沿用个人固定工作流 True-V3 GGUF Q5_K / 2 步，同一组四图，来源任务 `ac5f02a90352f2a9ac6b7a59ba6157a0806c141a70310bef3069870541563f45`。提交前确认 ComfyUI 队列为空。

使用实例内部 WebSocket 的 execution_start、execution_cached、executing、execution_success 事件，在同一测量进程用 perf_counter 记录时间。每个节点从 executing 到下个节点 executing / execution_success 计时，因此包含节点间调度与事件投递开销，是节点区间墙钟时间，不是 CUDA kernel profiler。模型加载节点返回后仍可能在编码/采样节点内发生实际模型搬运，不能把 Loader 一行当作全部模型驻留成本。全程没有主动清缓存或卸载模型，首轮仅表示未命中节点缓存，不表示机器冷启动。

结论：在相同输入和工作流下，重复输入缓存节省约 0.91s；后两轮采样节点都约 6s。因此“重新上传导致缓存失效”不能单独解释用户实测 3 秒多与当前 8 秒多的差异。本次没有复现同条件下的 3 秒多，不据此判断用户计时口径；还需要其具体工作流/输入条件作同条件比较。

本次仅新增诊断报告与原始数据，没有新增生产算法或 Schema，无迁移/回滚操作。实验脚本在云端个人服务目录独立运行，未植入 ComfyUI，也未把输出回贴到用户工程。
