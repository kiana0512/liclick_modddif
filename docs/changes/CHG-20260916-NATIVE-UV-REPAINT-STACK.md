# 合并 UV 后多次局部重绘显示修复

## 范围

- 主模块：M07 UV 常驻显示与组合缓存。
- 协作模块：M08 局部重绘图层、M09 图层顺序和显隐。
- 算法版本：`UV-DISPLAY-BUFFER` v1.5.2。

## 问题与修复

合并 UV 之上连续创建两个原生 UV 局部重绘层时，最新一层由独立顶层采样器显示，较早一层应与合并 UV 组成下层纹理。旧代码为该下层纹理生成缓存键时过滤了全部局部重绘层，因此第二次重绘会命中“仅合并 UV”的旧缓存；图层行和眼睛状态正确，但模型只能看到最新一层。

显示缓存现在以 `nonLiveUvLayers` 的精确签名为键。该集合只排除当前顶层快速采样层，并保留所有较早的可见重绘层、合并 UV、图像 URL、相对层序、透明度、混合模式、颜色调整和内容 revision。异步组合完成前继续保留同键的有效纹理，完成后原子替换。

## 对等路径审计

- GPU/shader：不改 source-over、颜色空间、顶层采样或材质 uniform；只修正下层组合的缓存身份。
- CPU/Worker：继续由现有 UV Worker 按 `compareUvLayersForComposition` 自底向上合成，不改像素公式和完整分辨率。
- 合并 UV：`compareUvMergeSources` 仍按面板顺序消费全部原生重绘层。
- 保存和恢复：Layer 数据、URL、order、visible、opacity 和 revision 均未改写。
- 导出：`texturedExportUtils` 继续通过 `getVisibleUvLayerStack` 消费全部可见 UV 层；不引入视口专用替代结果。

## 验证

- 真实 WebGL 像素回归：合并 UV 上放置两个互不重叠的原生 UV 重绘层，旧层区域红通道均值 221.8，新层区域绿通道均值 198.1，两层同时存在。
- 关闭旧层眼睛后对应区域红色覆盖消失；重新打开后旧层红色覆盖与最新层绿色覆盖同时恢复。
- 同一测试继续覆盖投影式双重绘、合并 UV 边界、几何显示模式、90 帧相机交互与 UV 岛边缘上传一致性。

## 迁移与回滚

无 Project/Layer Schema、资产或派生持久缓存迁移。刷新后按当前图层栈重建会话内显示缓存。回滚本次 `SceneRoot` 缓存键修改及对应回归即可；已保存图层和纹理资产保持可用。
