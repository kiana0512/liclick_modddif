# 高面数模型导入前确认减面

- 主模块 M02，协作 M10/M13；算法 `IMPORT-DECIMATE` v1.0.0。用户批准：超过 150 万三角面弹窗，确认后通过服务端 Blender 简化至约 20 万面，再检查 UV；异常 UV 单独确认后重新展开。输入样本实测后接入。
- 此完整方案跨导入编排、确认 UI、认证服务端与 Blender，按用户已批准方案集中实现，超过默认五文件范围；不扩展独立拓扑页，不替换 Asset V4 的生产重拓扑服务。

## 行为与门禁

导入先统计所有 Mesh 三角面总数。严格大于 1,500,000 才询问减面，恰好该数量不触发。原有 200 万面绘制门禁移到处理完成之后，因此超过 200 万面的输入可以先尝试简化，未确认或处理失败不会绕过门禁进入工程。

确认框显示实际三角面数、目标约 20 万面、细节/纹理可能受影响，并提供取消后自行处理的选择。取消、Escape、切工程均终止本次导入。减面授权不包含展 UV 授权：减面完成才执行既有 UV0 检查，UV 正常原样保留；越界、缺失、非有限、退化 UV 才再次弹窗。拒绝展 UV 则整个候选模型不进入工程。

新路由 `POST /api/asset-processing/import-decimate?consent=change-topology-v1` 沿用 asset-processing 的 Origin、认证和静态内嵌 GLB 校验。UV consent 不可用于减面，拓扑 consent 不可用于 UV。与 UV 修复共用一个处理槽、256 MiB 输入/输出限制、180 秒 Blender 超时、210 秒客户端超时、断连中止和临时目录清理。仅接受静态模型，不执行上传脚本或读取外部资源。

服务端 Blender COLLAPSE Decimate 按各对象原三角面数量分配总计 200,000 面预算，输出三角化；预算是整个文件的总数，不是每个对象 20 万面。每个对象最少分配一面，结果不得出现空对象。保持对象、原坐标、材质和 UV 数据，不在该步骤重新展开 UV。结果及序列化 GLB 回读均检查对象数量、有限位置和非零总面数；允许目标上方 1% 的算法余量，超过则报错。客户端独立检查面数，并在完成可选 UV 修复后复检。约 20 万是简化目标，不承诺所有网格恰好 200,000 面，也不称为规则四边形重拓扑。

UV 修复保持 `IMPORT-UV-REPAIR` v1.0.0 的展开/排布/内缩公式和 QA，不放宽现有绘制要求。重展仍不转烘焙原纹理，因此确认框明确旧纹理可能错位。处理准备按需加载，避免增长编辑器初始包体。

## 保存与回滚

所有步骤通过后才注册场景、创建图层和保存资产，保存最后一步实际生成的 GLB，重开和导出使用同一套几何/UV；保留源物理单位。原文件不覆盖。取消和失败释放原候选、处理中间模型、纹理和 blob URL。旧工程不自动减面或展 UV。

CPU/GPU/Worker/shader 无独立减面分支，均读取最终注册的几何/UV；绘制分辨率、烘焙 QA、工程 Schema、Command/CAS、资产归属不变。无数据库迁移。回滚关闭减面入口并恢复导入前原面数门禁；已生成 GLB 继续作为普通资产保留。

## 验证

- 用户汽车 FBX 原始 1,999,546 三角面。独立 A100 Blender 5.1.2 减面约 30 秒，导出回读 199,999 面，UV 越界及退化均为 0；同相机灰模对照，整体外形保留，局部接缝/曲面细节有损失。
- 接入后用真实网页加载器把该 FBX 打包内嵌 GLB，调用隔离环境中实际 HTTP handler 和新 Blender 脚本，返回 28,336,252 字节 GLB。未调用或修改在线用户工程。
- 新流程实际输出回读为 200,000 三角面，缺失/越界/非有限/退化 UV 均为 0，不调用展 UV；最终 File 再加载结果相同。浏览器测试的 190 MiB 上传触发 CDP 转义字符串大小限制，因此大文件场景在 fetch 边界注入独立 HTTP 实测结果；模型加载、打包、弹窗、回读和小样本交互均执行真实代码，服务端 HTTP/Blender 单独实跑通过。
- 浏览器回归覆盖严格阈值、超过 200 万面进入减面流程、取消/Escape/切工程不请求、失败释放资源、UV 正常不请求修复、第二次确认取消阻止导入、两阶段成功后保存 File 再加载。
