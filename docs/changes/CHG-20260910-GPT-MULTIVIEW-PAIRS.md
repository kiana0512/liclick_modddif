# GPT 多视图固定相对视角分组

主模块 M04，协作 M03/M05/M06/M12/M15。维护版本 2.19.15；新增 GPT-MULTIVIEW-PAIR-SEQUENCE v1.0.0。

发布集成版本 2.19.16：合入远端 master 814651b，保留 M03 相机平滑取景/新相机作者蒙版捕获和 M13 普通模式性能浮条隐藏。测试登记保留双方用例；包体保留双方已记录增量，editor 498,512 / total 3,160,000，正式发布重新测量。无像素、Schema 或数据迁移变更。

## 执行契约

- 预设 1：前/后 → 左前/右后 → 左/右 → 左后/右前 → 顶/底。
- 预设 2：前/后 → 左/右 → 右上/左下 → 前上/后下 → 左上/右下 → 后上/前下 → 顶/底。
- 自定义基础预设：前/后 → 左/右 → 顶/底。向预设增加角度虽然 UI 切到 custom，继承的原预设角度仍使用原固定配对；用户新加视角逐个生成，位于顶底之前。
- 不改变列表顺序、相机方向/up、用户草稿、参考图或新增 GPT/远端 UI；不猜测/替换用户角度。缺少一方时只生成现有视角，同一 id 不重复提交。

## 数据流与失败

纯配对规划、组间串行、组内等待与固定顺序提交、实际材质准入检查放在 engine/generation/gptMultiviewPairs.ts。React 只提供现有请求、捕获、工程与视口端口。复用原单/多视图批次事务，内部 pairContext 避免重复账号校验、末尾补缝和 toast。

每组串行捕获相机/白模/深度/完整 mask，再从当前实际颜色生成补全引导图；已有纹理使用原 completion 构建器，空白使用 initial 构建器。两张输入均准备并持久化后才并行提交/等待；两张成功结果按固定顺序走原 addGenerationAsProjectedLayer 串行事务，不由返回速度决定层顺序。预览冻结只作用于本组，释放后验证所有可见 mesh 的真实材质 bindings 包含本组仍可见图层，并经过两次 waitForBrowserPaint，才准备下一组。无依据的 resident 事件、旧行数或超时不能放行。

所有组共用 textureBatchId；后续组不预创建 running 任务。某视角失败时仍保存/回贴成功兄弟项，然后停止后续组；展示真实失败原因，历史可恢复。取消沿用既有本地丢弃、晚提交取消和同批取消机制。工程/模型切换不继续下一组。删除/隐藏不复活（复用投影提交回执）；显示超时停止后续，不降质、不强行假定完成。整轮成功后仅补缝一次。

相对视角只是减少重叠：透视、凹槽/镂空、薄片双面模型仍可能有交叠；保留原投影深度/朝向/遮挡质量算法，不宣称零接缝。

## 对应路径审计

只改变客户端调度与捕获时机。仍使用已有完整分辨率 generation input Worker，原 mask/depth 与模型内外轮廓裁切规则不变；不修改 GPU shader、CPU/Worker UV 合成、历史蒙版、橡皮、导出、颜色或深度公式。复用原 verified asset 保存、Command 幂等和 Revision CAS，不引入服务端接口、Schema 或历史资产迁移。单视图保持原即时发布；旧远端兼容分支保持。
