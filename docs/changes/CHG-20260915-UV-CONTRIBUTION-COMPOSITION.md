# M07：逐层 UV 贡献、无损溢出与显隐合成

状态：本地实现/验收中，未推送，不能宣称任意组合实时。

用户授权：改为 UV 贡献混合、大改核心链路；目标是实时按钮实时画面，不允许普通显隐因缓存淘汰重投影。主模块 M07，协作 M06/M09/M11；算法 `UV-LAYER-CONTRIBUTION/1.0.0`。本轮超过常规小补丁规模，仍只处理同一个显隐瓶颈。

## 数据流与不变量

投影输入变化 → 原有完整分辨率光栅 → 每层颜色/质量 UV → 精确 64×64 稀疏瓦片 → 原有 GPU Top-3 混合 → 原有舍入修正、接缝/gutter → 实际材质绑定。

- 显隐不改变逐层 key；已有 GPU UV 直接参与混合。GPU 空间不足时先无损保存贡献，再释放；已归档贡献恢复失败明确报错并保留上一帧，不偷偷重投影。
- 仅删除所有 alpha 为零的瓦片。alpha 1..5 虽不参与 Top-3，仍进入覆盖计数，不能被删。瓦片保留原始 RGBA8/R8，整数寻址、无缩放、无重采样；高密度层保留原目标。
- GPU 输入预算 256→512 MiB，最终显隐结果预算 512→256 MiB，两级名义总预算仍为 768 MiB。Top-3 ping-pong、瞬时读回/恢复 scratch 不包含在此预算，未声称全进程峰值不变。
- 溢出使用浏览器 IndexedDB 会话独占 namespace；原始 GPU 行序、颜色与权重无损 deflate（不可用时原字节）。恢复按 128 KiB 上传，不重新解码投影源，不改变源资产。
- 新增普通 UV 最终 RGBA 直传，按原行序反转成 GPU 行序，保留 SRGB、直 alpha、线性过滤/无 mipmap 的既有 sampler profile；128 KiB 条带、4ms 让出、交互静默与取消保护。交互橡皮仍走已有 Worker/patch 路径。
- CPU 稀疏舍入标记扫描仍检查每个像素，只按 4ms 时间预算让出，不再每 1MiB 强制让出。

## 对应端审计

- GPU/shader：新增瓦片寻址，不改 Top-3 排序、质量、颜色一致性、透明度或舍入公式。
- CPU/Worker：原像素 oracle、读回 Y 翻转、接缝与 gutter 不变；未禁用设备校准和 QA。普通最终上传替换位图中转，不替换生产 UV/PBR 算法。
- 生成：仍等待最新完整 UV 实际绑定屏障，下一轮截图包含之前图层的最终显示。
- 持久化/导出：Project Command 幂等、Revision CAS、ownership、verified assets、工程 schema 和导出参数不变。新 IndexedDB 仅为会话派生缓存，不是工程资产协议。
- 原生 UV、overlay、live 绘制和显式 CPU 对照维持原路径。模型几何/UV、来源、蒙版或投影参数改变允许生成新的贡献；context loss/新会话必须重新建立有效 GPU 状态。
