# CHG-20260829 局部重绘多模态智能润色

## 变更身份

- 主模块：`M04` 生成编排，协作模块：`M03` 场景、相机与捕获、`M08` 局部重绘。
- UI：`UI-05` 生成面板。
- 算法：`ALG-GEN-005` 从 `1.0.0` 迭代到 `1.3.2`。

## 问题

旧版局部重绘智能润色只把对象名、参考图文件名和“是否有蒙版”写进文本消息。远端润色服务看不到当前效果图、真实白色蒙版或参考图像素，因此无法可靠识别蒙版位于哪个结构，也无法从多视图参考中找到对应材质与文字。

v1.3.0 直连 Qwen 后，真实工程仍可能把 4K WebP 参考图和两张 2K 无损 PNG 原样提交给代理；这与插件统一 JPEG quality 85 的输入契约不一致，会触发上游格式或请求体限制并表现为通用“智能润色暂不可用”。v1.3.1 在服务端边界统一完成最长边 2048、JPEG quality 85 规范化，透明区域落黑，视觉语义与顺序不变。

v1.3.1 的 Image 1 虽然声明为 2048 方图，但浏览器实际只渲染 512px，再由编码 Worker 放大到 2048px；放大无法恢复文字边缘、锈迹与细小材质。v1.3.2 只修正当前视角效果图：改为真实 2K 分块渲染，并在上游边界使用 JPEG quality 95 / 4:4:4；参考图和蒙版保持原编码参数。

## 实现

1. 点击局部重绘智能润色时冻结当前对象与方形相机，生成相互对齐的 2K Image 1 和 Image 3 RGB mask；Image 1 使用干净视口效果语义，以 512px tile 分块组成真实 2048px 输出，保留当前材质、灯光、背景和网格，仅隐藏画笔、选中辉光、线框与实时重绘预览等编辑叠加。该采集不创建 Project Capture，也不闪烁切换视口。
2. Image 2 使用用户当前选中的完整参考图；只在约 20 MiB data URL 的独立视觉输入安全预算需要时执行保尺寸优先 WebP 压缩，不假定或裁改参考图布局，避免普通工具调用预算过小造成多视图文字和细节丢失。
3. 浏览器通过同源 Cookie API 提交三张 data URL。Node 控制面要求三图齐全，只接受 PNG/JPEG/WebP，单图解码后最多 16 MiB。
4. Node 上游边界仅对 Image 1 使用 JPEG quality 95 / 4:4:4，参考图和蒙版继续使用 quality 85 / 4:2:0；三图最长边均不超过 2048。该差异化编码只增加当前效果图细节，不扩大其他输入或生成链路。
5. 仅局部重绘智能润色由 Node 控制面直连公司 OpenAI-compatible 代理，模型固定为默认 `qwen3-vl-plus`；Qwen user content 严格按 `Image 1 当前效果图 → Image 2 完整参考图 → 白色蒙版` 顺序附加三张 `image_url`。普通单视图和多视图继续调用莉刻 `data-analysis`，不进入 Qwen 分支。
6. Qwen system content 使用产品确认的 FLUX.2 Klein 模板，运行时只替换用户要求、蒙版说明、Image 1/2 说明、必须保留和必须避免字段。返回仅允许四段英文提示词，继续执行每段 1–3 句及总计 130–220 词的 fail-closed 校验。
7. 等待期间若原提示词、蒙版 revision 或当前选中参考图 ID 发生变化，远端结果不覆盖当前输入。局部润色缺图时 fail closed，不再退化成文件名推断。

## 不变范围

- 普通单视图和多视图智能润色仍为莉刻纯文本 A2A，输出规则和保存字段不变。
- ModelView 局部生图仍接收当前效果图、材质参考图、RGB mask 和提示词四输入；本次只改变前置提示词润色。
- 不改变 Project、Layer、Generation、Capture Schema、Project Command、Revision CAS、ownership、对象存储、投影、UV、橡皮、导出或输出分辨率。

## 迁移与回滚

- 无项目数据迁移；三张润色图片只存在于浏览器到同源服务、以及服务端到公司 Qwen 代理的单次请求内，不写入 Project、对象存储或普通日志。API Key 仅由服务端环境变量注入。
- 回滚只需把局部重绘分支恢复为莉刻纯文本/A2A；现有提示词与历史工程无需改写或删除。
