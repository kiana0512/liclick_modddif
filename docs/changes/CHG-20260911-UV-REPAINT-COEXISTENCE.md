# 局部 UV 重绘多层预览共存

- 主模块 M08，协作 M03/M05/M07/M12。
- 显示绑定策略 UV-REPAINT-PREVIEW-BINDING v1.0.0；不修改笔画算法版本、native-v1 ID 或 Project Schema。
- 用户已于 2026-09-11 授权推送 master 并部署 A100；实际发布结果以部署后版本/健康检查记录为准。

## 根因及修复

1. 最上方 UV 重绘使用实时 sampler，旧层移到普通 UV sampler。普通图片加载器不能解码 `liclick-live-projected-canvas:`，旧纹理无法就绪。现在同步从 registry 借用原 GPU 纹理（释放 GPU owner 后为 committed Canvas），不走静态解码、分条上传或 LRU，不转存新图片。
2. 显隐同步和最终材质校验只将普通 UV 计入底层 sampler，遗漏下方局部重绘，即使借用纹理成功也将 opacity 清零。现在下方重绘存在时保留精确预览纹理及其合成透明度/颜色语义，不用普通 UV 缓存覆盖它。
3. 隐藏最上方重绘层也会改变 sampler 分配；原逻辑仅在打开图层时重建。现在局部重绘显隐两方向均触发材质校验，普通投影显隐仍保持原 uniform 快路。
4. 存在合并 UV 底图时，普通单层直读捷径不能绕过下方重绘层；混合底层走现有完整 UV 合成。混合底层成员显隐也触发精确重绑定，不能只改整张合成图的 opacity。

## 路径审计

- GPU：只改变纹理绑定和显示状态；借用 RT 的创建、保留、替换和释放仍属于原 UV 会话。没有额外 RT、全图读回或笔画计算。
- CPU/Worker：三层及以上仍使用现有非顶层合成与 live revision；不修改 alpha、顺序、源遮罩、分辨率或颜色转换。
- Shader：无公式/源码变化，不扩大绘制范围，不重新引入穿透、白点补洞或自动合并。
- 历史、保存、合并、PNG、FBX：原 committed RGBA 和 flush barrier 不变，不改图层像素/可见性持久化协议。Command/CAS/ownership/verified assets 不变。
- 旧 PNG 层仍走静态缓存；内存纹理不归静态缓存所有，不能由它 dispose。隐藏层不删除，重新显示不要求重新生成。
