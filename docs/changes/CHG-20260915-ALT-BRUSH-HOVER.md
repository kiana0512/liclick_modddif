# Alt 导航避开原生画笔悬停拾取

- 主模块 M03，协作 M08/UI-06；ALG-VIEW-INPUT-001/1.3.1。
- 根因：R3F 已跳过 Alt 导航拾取，但 SurfacePaint 的原生 pointermove 仍排队更新画笔，下一帧遍历模型计算命中。旋转、平移、缩放均被这条独立路径拖慢。
- 修复：原生悬停复用导航 pointer 所有权；Alt 按下或仍处于已锁定导航拖动时取消待执行悬停并隐藏画笔光标。松开 Alt 后仍按原拖动归属处理；按钮释放后悬停恢复，绘制中的输入先由原笔画处理。
- 验证：执行实际原生悬停调度器与 R3F 所有权，三种 Alt 拖动共 600 次跨帧事件均零多余拾取，覆盖中途松 Alt、旧悬停取消、松按钮恢复、绘制保护；既有相机、滚轮、取消/丢捕获、选择和笔画回归通过。未重新运行用户工程暴力压测，不宣称所有长帧已消失。
- 审计/回滚：相机轨迹、速度、按键含义、GPU/CPU/Worker/shader、QA、分辨率、投影/UV/导出、保存协议不改；无数据迁移。回滚共享导航查询与原生悬停 guard 即可。

## 首次接触前的 Alt 悬停

M03 / ALG-VIEW-INPUT-001/1.3.2：R3F 的 move guard 原先只检查 pointerdown 已锁定的指针，漏掉先按 Alt、尚未按鼠标的阶段。现在复用同一个导航所有权判断。安装版本 R3F dispatcher 配有 hover handler 的回归中，旧实现每种按钮开始前 120 次移动均拾取，新实现零拾取；三类导航、抬键、点击尾事件与普通悬停恢复通过。该回归证明入口漏洞，不单独证明用户工程首帧延迟全部由此导致；实际输入录制继续定位。

无像素、相机轨迹、按钮语义、资源或 Schema 迁移。回滚只恢复 R3F move 的旧判断。
