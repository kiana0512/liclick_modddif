## 后续体积与交互优化准则

不能以持续上调预算或每次削减几百字节作为优化策略。每次迭代记录总 JS、受限 chunk 字节与余量；同时记录真实场景的首屏/首次操作耗时、P95/P99 帧间隔和主线程长任务，不能用平均 FPS 代替交互验收。

优先顺序：共享重复算法和着色器片段；清理确实不可达的生产代码与重复依赖；按使用入口延迟加载重型模块，并在真实用户意图时预热。拆 chunk 仅改善加载时序，不算总包体减少；不能把成本移到首次拖拽/切层时。Editor 与 bake chunk 也必须逐项满足原预算，不能只看总量。

每项优化独立验证原像素/资产/取消与资源清理契约，测量前后差异，再决定保留。需要更大的功能预算时单独说明新功能成本与权衡，不能借性能修复放宽门禁。本次格式压缩减少传输和解析文本，不据此宣称视口帧率或所有交互卡顿已解决。
