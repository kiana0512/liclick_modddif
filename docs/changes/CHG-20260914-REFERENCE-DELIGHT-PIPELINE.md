- 主模块：M04；入口：UI-05。算法：`MULTIVIEW-REFERENCE-PIPELINE/1.0.0`、`MULTIVIEW-REFERENCE-PROMPT/2.0.0`。
- 用户授权：按实测配置先用 GPT-Image 2.5 Sunburst low 生成六视图，再把结果交给同模型 medium 去光，最后返回前端。两段提示词采用用户提供原文。
- 状态：本地实现；未推送、未部署，未额外提交付费生图。控制流验证不能替代真实输出的美术验收或耗时测量。

## 行为与边界

手动生成配对多视图、生成纹理前自动补齐多视图，均由既有 `generatePairedMultiviewReference` 入口请求新流程。前端固定 3:2，沿用用户明确选择的 1K/2K/4K 尺寸；auto 沿用显式比例时的既有 1K 解析规则。服务端强制第一轮 Sunburst / low / count=1，保留第一轮原提示词及用户补充。第二轮 Sunburst / medium / count=1，仅以第一轮的完整结果为参考，沿用比例与尺寸，使用独立、固定去光提示词，不混入原始单图或补充要求。

算法位于服务端 `referenceDelightPipeline.ts`；React 仅负责请求标记与进度展示，原轮询/持久化入口只接受整个任务成功后的最终图。第二轮允许即时返回图片或返回异步 taskId。服务端 jobId 始终不变，远端 taskId 切换；两轮使用同一用户 atlasHomeDir。普通单图、纹理多视图及局部重绘不带新标记，保留原行为。已有可复用多视图不自动重跑。

## 幂等、取消、恢复

沿用客户端请求 ID、项目/用户任务归属校验、服务端提交 promise 和 polling single-flight。第一轮结果不写入公开 resultUrl/resultUrls；第二轮完成才发布，不会让中间图进入参考资产或后续纹理流程。

第二轮提交前严格保存意图；磁盘写入失败则不发起第二轮。持久化记录中保留第一轮 URL、原 taskId、第二轮提示词、阶段。已有第二轮 taskId 时刷新/重启继续查询该任务；恢复到 submitting 但尚无明确回执时失败并提示，不自动发起另一笔生成。网络重试仅沿用已有的素材上传/结果轮询策略，不包裹生图提交。明确取消后，迟到回执不会恢复成功或发布结果。任一阶段失败均停止流程，不返回第一轮替代结果；手动重新生成仍是新任务，本次没有新增“仅重试第二轮”入口。

生成日志为服务器内部恢复文件，新增 `input.referencePipeline='six-view-delight-v1'` 与可选 `referenceDelight`，算法版本承担该附加字段的兼容版本。无标记旧任务保持单阶段。Project Schema、Command v1、Revision CAS、ownership 和 verified object assets 不变；无工程/资产迁移，不改投影、UV、GPU/CPU/Worker/shader、QA 或导出。
