# 橡皮擦连续性与交互 UV 显示候选

## 范围与证据

主模块 M08，协作 M06/M07，UI-06/UI-10；候选 ALG-ERASE-001 v1.3.9、UV-DISPLAY-BUFFER v1.1.1。实施 Codex，真实体验验收维护者。用户在跨模块方案说明后回复“可以”，批准实现；随后提供 Modddif 录屏作为交互参考。当前仅本地候选，未推送或部署，不能宣称 4K 跟手问题完全解决。

用户录屏 20260912141524_rec_.mp4（21.41 秒）及截图显示断续圆形擦除，并报告松手后才更新。代码检查发现两个独立原因：

1. `shouldCollapseSurfaceStrokeToLatestSample` 把普通投影层橡皮也归入每帧仅最后一点；但其可见/提交笔迹是 UV stamp，`getStrokeSourceUv` 仅连接同三角面。快速移动跨面时中间命中被丢弃，产生孤立圆点。
2. SceneRoot 的 WebGL2 常规显示采用 ResidentProjectedUvDisplay，活动投影列表为空；橡皮实时更新仍通过旧投影材质的 liveEraserMaskTexture。新常驻 UV 合成在指针交互期间暂停，完整像素提交后才重建。不能把最终合成 UV 的 alpha 直接乘橡皮蒙版，那会误擦其他图层。

Modddif 录屏 20260912144425_rec_.mp4（8.30 秒）可见擦除区域随拖动扩大、多个印迹连接；图层面板显示已合并图层。它验证的是用户想要的交互效果，不证明内部采用 GPU、脏瓦片或某种混合算法，也不能用于推断多投影层吞吐或精确输入延迟。

## 本次已实施：连续性

普通投影橡皮回到已有 UV 画笔密集表面采样路径，保留 coalesced 折线路径、压力插值、每帧最多 96 次采样和原笔刷间距；不改跨三角面/UV 岛的安全断线规则。不改变选择蒙版/局部重绘的相机空间输入路径。该修复减少正常快速拖动的漏点；极端单帧超长路径仍受 96 次预算限制，不承诺绝无漏点或帧率提升。

GPU/CPU/Worker/shader 覆盖公式、投影/UV/export、蒙版提交和高分辨率细化、历史事务、Command/Revision CAS、ownership、verified assets、Schema、输出分辨率和 QA 均不变；无资产迁移。回滚本次采样策略即可。

## 交互 UV 候选（已批准并实现，性能尚未达标）

跨 M08 橡皮编辑与 M06/M07 常驻 UV 合成。按系统准则第 14 节确认后实施：

- 普通 projected-mask 编辑创建独立完整分辨率草稿。笔画 union 从本笔基线重算，避免重复擦除羽化；快照不可变，只替换当前层蒙版，其他层和 Top-K/顺序不变。草稿与提交共享相同 Canvas 像素操作。
- 拖动期间允许唯一一个交互 UV 合成任务，后续输入只保留最新版本；不在每次移动时取消在途计算。复用正式全分辨率 UV、QA、接缝与纹理岛 gutter 流程；并非脏矩形 GPU 重合成。选择全流程是为避免局部后处理与最终合成不一致，已向用户说明这一阶段调整。
- 临时快照只注册到运行时图像表，使用后释放，草稿不写 LayerStore、压缩/磁盘缓存或历史。已呈现的旧交互缓冲清理，保持原有有界缓存。
- 正式 UV 按图层 mask URL 与 live revision 确认真正呈现，之后完成切层交接；交互草稿不满足生成截图的正式呈现屏障。撤销、重做、对象释放及空笔画清理草稿；取消/失败后可恢复相同签名的正式缓存。
- 原生 UV 与局部重绘橡皮的现有显示路径不变，不通过改最终合成 Alpha 来模拟单层擦除。

GPU canonical Top-K、CPU 舍入修正、Worker 合成、遮挡/角度/Alpha、接缝/gutter 与 QA 沿用现有正式管线。1K/2K/4K 不降采样。只增加编辑调度及运行时输入快照，不修改投影/UV/export 公式。画笔提交操作抽取为共享函数，保持普通笔刷 source-over、橡皮 destination-out、投影 keep-mask 黑底不透明语义。回滚时移除草稿接入、呈现确认与交互调度，并恢复提交函数；已保存蒙版保持可读，密集采样修复可独立保留。无资产迁移，不删除用户资产或历史。

## 验证状态

已通过专项采样、历史事务、Resident UV、Web typecheck、改动源码 lint 及真实隔离 Edge/WebGL 测试。夹具使用实际 ViewportCanvas 和两层不同颜色：按下未松手时上层被擦、下层仍在；继续拖动、松手、切层、撤销/重做验证通过。草稿 1024/2048/4096 全 RGBA 与冻结旧提交操作逐字节一致，重复 flush 不加重羽化，快照不随新笔画变化。1K 10/14 层用例通过，但不是用户复杂原工程。
