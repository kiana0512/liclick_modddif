# CHG-20260910-LOCAL-BOUNDARY-REPAIR

## 范围与原因

- 主模块 M07，协作 M05/M06/M08；LOCAL-BOUNDARY-REPAIR v1.0.0；文档 2.20.4。
- 用户反馈鱼嘴补缝颜色突兀，要求参考缝周围颜色。旧生产策略允许无限距离传播、跨一次接缝，并对没有来源的区域使用全图平均色；核心还支持整块锁定单个来源，不能保证局部色彩自然。
- 用户确认发布到 master/A100；发布采用带 Git SHA 的 Cloud 构建，仅替换三处 dist 与版本元数据，备份旧产物并保留 runtime/非版本配置，健康检查失败回滚。

## 实现与边界

生产策略启用 localBoundaryBlend，最大传播距离为 max(4, ceil(max(width,height)/128))，对应 1K/2K/4K/8K 的 8/16/32/64 texel；最小来源 alpha 为 224。强制禁止跨 UV 区域接缝传播、整块单来源锁色、全图平均色兜底，保留无可靠来源的缺口。原 gap 筛选、覆盖裙边及透明 RGB bleed 不变。

先拓扑内最近有效来源传播，再对真正补上的 texel 做固定原始边界的四邻域 Jacobi 颜色插值。仅同 UV 区域的可靠边界或已补像素参与，原始来源颜色 RMS 差超过 48 时不混合，避免明显材质颜色被平均。颜色门限使用冻结来源，不随扩散放宽。8–64 次迭代，只分配每个修补像素 3 字节的临时 RGB；不修改已有有效像素、输入数组、模型孔洞和 alpha 策略。循环检查取消，输出仍为独立稀疏修补贴图。

这不是语义识别或纹理生成：嘴内与外皮处于不同 UV 区域时隔离；同一/重叠 UV 内不能保证语义材质隔离。大面积缺失不强行补满，应使用局部重绘。既有错误修补结果不会自动重新着色，用户需先撤销旧补缝或删除对应修补图层后重跑，不能自动删除历史数据。

## 对称审计

- CPU/Worker：同一核心函数、同一策略、同一协议标志；真实 Worker 与主线程输出逐字节一致。主线程兼容算法按需加载，正常 Worker 路径不把内核放进编辑器初始路由。
- GPU/shader：输入 UV 烘焙、拓扑和预览投影算法不改，不启用实验内核、不降低分辨率或关闭质量验证。
- 预览/UV 合并/颜色/FBX：继续消费同一独立修补 underlay；编码、合成顺序和导出流程不变，仅新生成的修补 RGB/覆盖范围按新策略改变。
- 持久化：不改 Schema、Project Command、Revision CAS、ownership、verified assets，不重写历史贴图。遗漏新标志的旧显式 API 调用保留原功能，生产策略始终开启新逻辑。

- test:content-aware-repair：24 项通过，包括双侧渐变、UV 区域与接缝隔离、强色差保护、局部颜色变化、孔洞/弱 alpha、无来源/超距离保留、确定性/取消/1K–8K 参数。
- test:regression：109 contracts 通过；TypeScript 与 Cloud 生产构建通过。
- verify-local-boundary-blend-browser.mjs：真实 Edge、2048×2048、同输入 main/Worker RGBA 差异 0；修补 16384 像素，保留 301056 无证据像素，全局兜底 0。PNG 编码再解码中心为 [140,80,95]，输入数组未变。主线程约 404ms，Worker 约 418ms（含启动和复制，仅合成样例，非用户工程性能承诺）。
- 非用户鱼模型原工程复现，不声称已完成该模型视觉验收。
- Cloud 总 JS 从同配置基线 3159715 增至 3162377 字节（+2662）；新增功能预算 3000 字节含发布元数据。编辑器降为 486072 字节，不放宽任何单 chunk 或质量门禁；完整输出分辨率不变。

## 迁移与回滚

无工程、图层或资产迁移。回滚策略和算法代码恢复旧行为即可；已经生成的修补贴图继续可用，不删除作者资产。默认不回填或重算旧修补，撤销/历史恢复规则不变。
