# 常驻线框的相机切换生命周期

主模块 M03，入口 UI-06；算法 `ALG-VIEW-SELECT-001/1.0.5`，生产视口资源生命周期修复。

## 问题与实现

4517 工具/显示模式录制出现最大帧 83.4ms、19 个错失刷新，输入到帧 P95 11.2ms、无超过 50ms 的单个长任务；LoAF 显示多个约 8ms 的后台 continuation 在同一长帧内累积，不能把全部延迟归因于线框。控制台另有 Three 并行编译轮询读取 undefined.isReady 异常。

审计发现 TopologyWireframeOverlay 的预热 effect 依赖当前 camera。透视/正交替换会 cleanup 并为同一份常驻材质再次编译；旧 promise 完成后仍释放该材质，影响当前编译或呈现。这一路径由真实组件回归独立确认，尚不认定是控制台异常的唯一来源。

相机通过 ref 在开始预热时读取，预热 effect 仅依赖 renderer 和模型 overlay。视口投影模式改变保留已启动预热及材质，模型真实卸载仍取消任务并等编译结束后释放。原 shader、wireframe 索引缓冲、颜色/透明度/depth 和 1×1 原几何预热保持。

## 验证与边界

- 执行生产组件片段与真实 Three 资源；初次编译未完成时连续替换 16 个透视/正交相机。旧实现编译 17 次，新实现一次，完成后当前材质不释放。
- 71 次显隐继续复用同一资源，仅真实卸载释放；投影性能安全、framebuffer 恢复、Alt/滚轮/画笔尾事件回归通过。
- 4517 新构建实际相机 12 次替换及线框/PBR/法线/平面切换录制：60.0 FPS、P95 16.8ms、最大约 17ms、错失刷新 0；未新增 isReady 异常。预设 2→自定义→预设 1 和视口面板两次开合单独录制：59.7 FPS、P95 16.8ms、最大约 33ms、错失刷新 2，仍需继续定位，不能宣称全部达标。
- CPU 仅生命周期变化；GPU 预热内容、Worker/shader、捕获 helper 排除、UV/重绘/导出像素保持。完整分辨率、QA、Command 幂等性、Revision CAS、ownership 与 verified assets 不改。
- 此修复不处理后台 UV/蒙版准备的任务调度，也不能证明所有按钮或初始加载无长帧。其他交互继续逐项测量。

无 Schema、工程或资产迁移。回滚 SceneRoot.tsx 的 camera ref 与 effect 依赖修改，恢复旧 camera 生命周期；不删除工程或缓存资产。
