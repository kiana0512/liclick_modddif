# 超限投影待显示与 UV 合成缓存

M06/M05，ALG-PROJ-007 v2.1.8；M09，UV 合成会话缓存 v9。

用户明确要求超限时保留数据、标记待显示、常驻引导合成 UV，禁止显示未通过等价性验证的分批结果。撤销自动分批预览准入；按设备 uniform 预算从底向上准入可见投影，其余保持原 visible/持久字段，仅在运行期发布待显示 ID。图层行琥珀色与文字标识，面板常驻说明，并通过原合并入口提交全部可合并可见图层（包含待显示和 UV）。不静默改眼睛、不删除资产、不在预览层修改合并输入。

冷打开超限工程先显示预算内底层；这不是完整结果，必须由常驻说明明确告知。已有待显示层在隐藏其他层或成功合并后重新计算。跨对象 pending 按对象隔离，卸载清理。

UV 重复合成缓存原来使用每次新建的 masked blob URL，导致相同作者输入仍 miss。现在先用作者输入及已有 live revision 签名查缓存，再仅在 miss 时执行相同 mask flatten。输出算法、分辨率、GPU/CPU/Worker/shader、导出、QA 不变。持久 Schema、CAS、ownership 和资产不变，无数据迁移。回滚恢复 SceneRoot 准入、面板和缓存入口即可；不得恢复已证实不等价的分批效果为默认。

验证：完整89项Web回归通过，类型检查及构建通过。正式打包的实际 LayersPanel 在独立浏览器中显示30层、2个琥珀色待显示标记、常驻提示；点击合成按钮得到 submitted=30、pendingIncluded=true，验证按钮未遗漏待显示层。该夹具没有执行用户项目GPU合成，不能代替实际工程输出验收。开发测试路径被SPA入口接管，改用5200隔离静态服务测试构建产物。临时构建产物已移出public，保存在系统临时目录，不进入发布。

缓存v9同时包含完整作者Layer JSON，覆盖相机近远裁剪、忽略Alpha、可见性策略等原简略签名未包含的字段，live资源版本仍由原签名捕获。未宣称4K首次合成耗时已达标。
