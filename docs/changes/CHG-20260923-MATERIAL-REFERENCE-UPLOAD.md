# 材质参考图自动适配莉刻上传限制

- 模块：UI-05 → M04；算法 `MATERIAL-REFERENCE-UPLOAD/1.0.0`，任务恢复 `REFERENCE-LIGHTING/2.0.1`。状态：本地 4517 修复，未发布此补丁。
- 问题：2752×1536 cooler 原参考 PNG 为 5,828,868 字节；无损 WebP 约 3.94 MB，但 Base64 JSON 请求约 5.26 MB。文件小于 4 MB 不代表请求可通过 4,000,000 字节网关。
- 输入/输出：明确材质角色的 PNG/JPEG/WebP data URL → 临时上传副本/既有 verified 对象下载 URL。原文件、已处理参考和工程记录不覆盖、不删除。普通莉刻参考、单图/六视图参考处理、已识别 GPT 纹理材质及 GPT 重绘第三图共用策略；法线、蒙版、捕获和未知结构输入继续像素精确路径。
- 策略：原图/无损 PNG/无损 WebP 优先；Cloud 已配置对象存储时继续 owned/verified 精确资产协议。无对象存储且仍超限时，先尝试 WebP near-lossless 100/80/60；解码逐像素验证原尺寸、精确 alpha、ICC、RGB 最大误差 2/255 与 RGB PSNR ≥45dB。仍不满足体积时，对无 ICC 输入尝试 RGB 低位舍入副本（步长2，误差≤1），再无损 WebP 编码，使用同一验证。
- 按维护者明确要求，4 MB 为硬限制且自动转换：极端高熵材质在以上步骤后搜索 1–100 中可容纳的最高 WebP quality，保持原尺寸、精确 alpha 和 ICC；该末级不承诺 2/255 或 45dB，绝不称为严格无损。如果透明通道本身不可压缩到预算或编码尺寸不支持，则阻止发送，不谎报成功或发送超限请求。
- 预算：材质 data URL 最多 4,000,000−65,536 字节；发送前原有完整 JSON 检查继续严格小于 4,000,000。不修改法线/结构图预算，不使用有损上传缓存替代像素精确缓存。
- 恢复：仅旧错误明确包含“当前服务未配置大图对象存储上传。未提交生成任务”、状态 failed 且无远端 taskId 的参考光照任务，推进一次已有 g 尝试编号。成功/运行中/已接受/不明网络失败不重提；旧失败历史保留，并发与重载复用同一新 ID。
- 审计：仅 CPU 上传副本编码和生成请求身份。GPU、Worker、shader、投影/UV、几何、蒙版、返图与保存/export 均不改。Project/Generation schema、Command 幂等、Revision CAS、ownership 与 verified assets 协议不变，无数据迁移。
- 验证：像素精确/材质上传回归覆盖 4K、无损、近无损误差/PSNR/alpha、高熵自动适配、完整 JSON 大小与 Cloud verified 失败关闭；光照回归覆盖旧失败迁移、并发、重载、账号隔离及禁止重复付费任务。现有 GPT 结合图上传、去光照/绑定回归及类型构建通过。真实参考图验证结果见完成报告；不以单元测试替代生图美术验收。
- 回滚：恢复材质角色路由、上传策略与旧失败迁移；已有 g1/成功任务仍按原协议读取，原图、结果、历史和项目保留。负责人：Codex；取舍依据：维护者本次要求硬限制、自动转换、尽可能保护质量。
