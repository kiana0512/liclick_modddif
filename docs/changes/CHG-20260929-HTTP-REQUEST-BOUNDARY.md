# 控制面请求体和异常响应边界

- 日期：2026-09-29；状态：待正式门禁和生产复验。
- UI/use case：浏览器和同源 Cloud API；M13 主模块、M15 验证；`HTTP-REQUEST-BOUNDARY/1.0.0`，Patch，无算法变更。
- 输入：已认证 HTTP JSON 请求及其 Content-Length/实际数据流。输出：预算内原样解析，超限返回 413，未预期服务端异常返回通用 500。
- 风险和根因：原 JSON 读取默认无上限，认证用户可令多个并发请求积累大量内存；全局错误处理将异常原文直接发给浏览器，可能泄露内部路径或上游细节。
- 规则：一般 JSON 默认 8 MiB；Project 文档/Command 128 MiB；旧 data URL 资产导入 224 MiB；莉刻编辑和 ModelView 原图请求 256 MiB，与生产入口一致；既有更小独立上限继续有效。先检查声明长度，再逐块检查实际长度。超限不解析、不进入业务处理，连接在 413 后关闭。全局意外 500 脱敏，服务端仍记录原始异常。
- 不涉及像素、颜色空间、矩阵、图像分辨率、GPU/CPU/Worker/shader、Project Command 幂等、Revision CAS、ownership 或导出格式。大请求边界影响传输容量，不改生成/投影/UV/局部重绘算法。
- 验证：真实 HTTP 回归覆盖正常 JSON、Content-Length 与 chunked 超限 413、意外 500 脱敏、文件响应中途失败；server lint/typecheck、全仓发布前门禁、生产 413/500 和健康探针仍需核对。请求体并发总内存仍需生产指标观察。
- 迁移/回滚：无持久化 Schema 或资产迁移。若合法旧 Project 文档超过 128 MiB，应先按资产引用规范清理内嵌内容再重试；回滚代码可恢复原传输行为，但会恢复上述风险。
