# UV 质量准备与校验让出主线程

- 主模块 M06，协作 M07/M15；新增 UV-QUALITY-SCHEDULING/1.0.0，UV-DEVICE-CALIBRATION/1.1.1，UV-READBACK-SCHEDULING/1.1.0。ALG-UV-003 v2.1.0 的评分、舍入、Top-K 和像素阈值保持。
- 问题：评分查找表重复同步构造、设备校准输入循环及完整 CPU/GPU 字节比较可占住主线程。取消旧底图请求不解决这些 CPU 工作。
- 修改：评分表使用同一个生成器保留同步 gold 构造，并在生产校准前按累计 4ms 让出任务；并行校准共享准备 Promise，只读 Float32 表跨 GPU 所有者复用，各纹理独立释放。校准输入和完整 QA 比较按块让出任务，所有调用者等待最终校验；context loss 后旧校验禁止写入新上下文批准状态。
- 审计：不改变 GPU/CPU/Worker/shader、UV topology、mask/depth、混合、接缝/gutter、分辨率、质量门禁、上传、持久化、生成屏障或导出像素。React/Zustand 不包含新算法；Command/CAS/ownership/verified assets 与 Schema 保持，无资产或历史迁移。
- 专项验证：分段表与同步表全部 Float32 字节一致，并行准备和独立 GPU 所有权；完整 4096² QA 给输入任务边界，末尾错误像素仍被拒绝，校验中 context loss 不批准新上下文。既有 Resident 精确舍入、重复元组、hash 碰撞及显隐调度测试通过。
- 浏览器：独立 6175 / Codex in-app Chromium / 4096² / 6 个图层 / 实际 Resident UV 与 Three 材质绑定，不读取用户工程。修改前首次 1272.6ms、主线程长任务 53ms；修改后首次 1172.7ms、长任务 0；未缓存中层切换 264.3ms、最大帧间隔 33.3ms、长任务 0。先前一轮首次 1455.8ms/196ms 长任务包含冷模块/JIT 成本，不能把它全部归因于评分表。驱动 getBufferSubData 单次仍有 5–11ms；新组合完整回读/修正/上传成本保留，不宣称所有工程无卡顿或所有组合实时。
- GPU 回读：每次同步驱动拷贝从 8 MiB 限制为 1 MiB；独立上下文最多八条并行、PBO 总量最多 8 MiB，可见上下文仍逐条等待绘制边界。直接写入唯一最终缓冲，出错先等待全部在途读取结束再释放目标。实际 Chromium/Three 4096² 回读 64 条、67,108,864 个 RGBA 字节与原读取完全一致；非整条尺寸、后提交先失败、资源释放回归通过。
- 验证要求：完整 Web 回归、最终 SHA 正式 prepush 产物预算与部署模拟通过后推送。本卡隔离夹具不提交付费生成；用户授权的十视图生成另见生成恢复变更卡。
- 迁移/回滚：无需迁移。同步回滚准备/校验调度及其 await 调用即可；保留工程源资产和 QA 门禁，不恢复退役运行时或投影视口展示。
