# 橡皮草稿增量确认与 UV 边界复用

- 授权：用户批准优化，并追加“上 master 和 A100”。
- 主模块 M08；协作 M06/M07，UI-06/UI-10。
- ALG-ERASE-001 v1.4.1 / UV-DISPLAY-BUFFER v1.2.1；基线 166ecfa，合入 master 3843176 的上传调度与显隐优化。

## 实施范围

草稿仍按累计笔迹从手势开始时的原蒙版恢复、应用原 Canvas 擦除公式。另记录每段变化及 revision：仅成功完成校验和上传后确认当前快照 revision，后续输入不被清除；下一轮 512/1024 计算窗口取未确认变化并集，而不是整条笔画累计并集。最多 128 条记录，超限合并为保守并集，失败不确认。切换、销毁与原有取消门禁保持。

只有几何校验缓存提供的不可变 topology 显式启用边界种子复用。缓存一份弱引用身份、尺寸和最多 262144 个 Uint32 索引（约 1 MiB）；密集边界超限回退原全扫描。动态 coverage 每次重新过滤；原行序、邻居顺序及立即写回传播不改。普通可变 topology 调用不缓存。冷扫描可能更慢，密集 UV 不保证受益。

## 一致性与生命周期

- GPU：复用上一版区域光栅、排序、完整纹理显示交接，未新增 GPU 笔刷或共享上下文常驻路径。
- CPU：保留双精度质量修正、完整图后处理、Canvas 蒙版及精确顺序传播；仅减少已发布范围重复计算与符合条件的重复邻居扫描。
- Worker / shader：通道、Alpha、Y 方向、阈值、覆盖和舍入不改，完整分辨率及 QA 不降级。
- 合并 / 导出：相同 gutter 种子优化仅在不可变拓扑入口启用，不改变输出内容；没有新增自动补洞。
- 持久化、Project Command、Revision CAS、ownership、verified assets 和历史/撤销格式不变，无数据迁移。

## 验证及限制

- 未发布 revision、提交期间新输入、260 段队列压缩、尺度换算、销毁等回归通过。
- 冻结旧算法对照覆盖 600 组随机尺寸/coverage/Alpha/迭代数；首次、重复种子复用及同 topology 改变 coverage 均逐字节一致。
- 2K / 14 层真实 ViewportCanvas 连续拖动、松手前可见、露出下层、撤销/重做与切层检查；完整区域对照覆盖普通层、重绘层、重叠 UV 和接缝共 12 组，差异为零。
- 短距离测试仍在一个 512 窗口内，A/B 未证明端到端明显提速，不能据此声称 CPU 占用显著下降。新优化主要避免长笔画已发布部分继续扩大计算窗口。
- 仍有源纹理上传、CPU 读回和后处理；不是全 GPU 常驻方案，未达到逐帧实时承诺。用户复杂工程仍需实测。

## 发布与回滚

提交后以正式 prepush 检查同一 SHA，随后推送 master、发布 A100；失败不切换服务。部署保留上一版本 dist 和运行配置，按原流程可恢复。不删除或修改用户工程资产。

算法回滚：去掉 revision bounds 参数/确认调用、恢复累计 dirtyBounds，并关闭不可变 topology 优化入口；原图层、蒙版及历史无需迁移。
