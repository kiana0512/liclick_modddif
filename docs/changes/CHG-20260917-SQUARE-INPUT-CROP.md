# 远端输入按长边完整方形裁切

- 主模块 M04，协作 M03/M08；算法 `GPT-CONTENT-FRAMING/2.2.0`。
- 状态：本地修改，未推送、部署或提交付费生成任务。

## 问题与修改

用户提供的车辆俯视输入 PNG 为 1629×1629，但中间行只有 x=424..1205 的 782 像素区域不透明，两侧 Alpha 为 0。旧代码计算长边方框后，又以较窄的 `cropBounds` 对 Canvas 做 clip，使原有背景在短轴两端被清空。

移除二次长方形 clip，直接以方形 Canvas 的边界截取源图。方框边长仍为物体长边加每侧 max(2,ceil(长边×1%)) 安全距离，保持原中心及整数平移；方框内原始背景和模型 RGBA 完整保留，不缩放、不拉伸、不填补原本透明的法线背景。超出源图的区域仍为透明，不推断颜色或生成额外像素。

GPT 贴图单/多视角与 GPT 局部重绘共用此输入适配器。局部重绘颜色与法线使用同一方框；材质参考、作者蒙版和保存的 capture 均不改写。ModelView 独立入口、参考图六视图生成和光照处理不走此适配器，本次不改变这些请求。

## 对应路径审计

- 改动仅浏览器 CPU Canvas 上传准备；GPU、Worker、shader 没有裁切公式副本。
- 服务端继续以 framing 中的 1:1 比例请求对应分辨率，上传字节由既有 exact-reference 通道处理。
- 方框位置、大小、subject、cropBounds 元数据和返回逆映射不变；cropBounds 仍表示含边距的物体范围，不能再作为清除背景的 clip。
- 投影/UV/export 消费原有恢复坐标；轮廓/尺寸 QA、分辨率、Project Schema、Command/CAS/ownership 与 verified assets 不变。
