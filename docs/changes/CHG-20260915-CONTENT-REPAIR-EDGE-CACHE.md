# 内容填补固定邻接判断缓存

主模块 M07，协作 M05/M06/M08/M09。LOCAL-BOUNDARY-REPAIR/1.2.1。

4K 十投影基准：3455202 个像素需要修补，首次总耗时 20145.2ms，repair-worker-ready 阶段 11463.4ms。Jacobi 局部边界混合最多 64 轮，原代码每轮重新判断拓扑归属、原始 donor、颜色距离；这些输入在混合期间均不变。

将四个方向的允许边预计算为每个修补像素一个字节，后续每轮只累加允许邻居。保留四邻居方向顺序、每轮 Uint8Clamped 舍入、原有 8–64 轮、原始颜色阈值及透明 RGB；不提前收敛或减少轮数。CPU fallback 和生产 Worker 共用同一核心。该 4K 项目新增临时内存约 3.3MiB；最多为像素数量字节（4096² 时 16MiB），函数返回释放。

验证：14 个核心测试通过；40 组变更前完整 RGBA/修补 mask/排除 mask 黄金字节保持一致，涵盖边缘、薄尺寸、区域分隔、无效拓扑和透明来源。512² 样例三轮原耗时 184.1/160.0/159.1ms，缓存版 126.2/103.6/106.8ms，60928 个修补像素输出一致。

相同项目复测总耗时 15341.9ms、repair-worker-ready 8529.2ms，修补数仍 3455202、输出 checksum 仍 3581058624。拓扑缓存与发布耗时不同，因此总耗时变化不能全部归因于边缓存；基准还包含显式交互暂停。全流程最大帧由 200.2ms 变为 100.2ms，仍未达标，原状态恢复/eye/texture/underlay 检查通过。

GPU/shader 的投影、UV 合成与导出不变；Worker 传输、原分辨率、QA、修补来源、透明度、Project Command/Revision CAS/ownership/verified assets 均不变。无 Schema/资产迁移，不重算旧结果。回滚删除固定边缓存并恢复每轮同样的合法性检查，不能降低迭代数或质量标准。
