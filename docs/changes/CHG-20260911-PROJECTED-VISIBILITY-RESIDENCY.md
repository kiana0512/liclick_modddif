# 投影图层恢复显示时保留已上传材质

- 主模块 M06，协作 M08/M13；ALG-PROJ-007 v2.1.12，实现与资源生命周期 Patch。
- 问题：关闭图层后从白模逐层恢复，最终输出能恢复，但经过单层路径时原完整多层材质被释放。随后每次增加可见层都可能重新准备纹理、编译与发布，延迟累积。
- 修复：模型范围内分别保留最近一份已构建单层和多层材质；白模、单层、多层之间切换不再互相淘汰。取出即移交所有权，只有当前材质不能更新时才取缓存。多层仍只接受至少两层的严格兼容有序子集，单层继续使用原单层 shader。来源、相机、排序或采样器配置变化仍走原工厂，禁止复用旧像素。
- 资源：最多保留两份脱离模型的既有材质，不预载隐藏图层、不复制 GPU 纹理；同类替换、失配、模型更换及卸载释放缓存。代价是切到白模后保留既有纹理，以缩短再次显示的等待。
- 审计：GPU 改变材质持有期，CPU 复用原兼容判定；Worker 解码/上传协议、shader 覆盖与颜色公式、深度/蒙版、UV 合成、导出、输出分辨率和 QA 均不变。Project Command 幂等性、Revision CAS、ownership 与 verified assets 不变。
- 验证：原 570 次多层显隐回归通过；新增 60 次单层/多层恢复以及独占所有权、同类替换、来源失配和幂等清理回归通过。独立 Edge WebGL 真实 ViewportCanvas 五层循环中，资源稳定后复用同一多层材质；重新开启各层的两帧采样与稳定输出相同。该小场景不等同于用户 4K 模型的延迟验收，首次资源准备仍可能等待。
- Schema 无变化，无资产或旧工程迁移。回滚此缓存类及 SceneRoot 接入即可恢复原释放/重建行为，不删除项目或生成资产。
- 实际验收：内置浏览器打开原割草机器人项目，4K，14 个投影层、6 个局部重绘层和内容识别底层。全关得到白模，再逐层恢复；材质构建计数只在首个单层从 2 增到 3，后续 19 个投影/重绘层恢复保持 3，最终图层状态恢复且无 console error。独立五层两轮恢复对照额外构建 10→1，两帧采样约 19–34ms，像素与稳定输出一致；该采样时间仅代表测试设备小场景，不作为原项目完整呈现延迟承诺。
- 发布前检查：Web 116 项回归通过，生产构建、类型检查、全仓 lint（0 error，保留既有 warning）、云边界、持久化边界、原包体预算通过。
