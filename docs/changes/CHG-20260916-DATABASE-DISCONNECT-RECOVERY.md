# 数据库断连保护与项目列表加载恢复

## 范围

主模块 M14，协作 M01/UI-01。POSTGRES-CONNECTION-LIFETIME v1.0.0；
PERF-PROJECT-LIST-001 v1.1.0。不涉及生成、绘制或 GPU 算法。

## 证据与边界

A100 PostgreSQL 容器内存上限仍为 1 GiB，排查期间 oom_kill 从 37 增到 48；
API 日志出现 Connection terminated unexpectedly 和未处理 Pool error，服务重启计数增长。
只读核对该用户 12 个未删除项目、8728 条 Revision；不据此宣称所有资源文件均完整。
列表 SQL 原来分别读取七个 JSONB 字段，会重复解压大文档；这是可消除的风险，
尚未通过数据库故障现场日志证明它是每次 OOM 的唯一触发语句。

## 修改

- 共享 Pool 监听 idle error，仅记录固定脱敏文本；坏空闲连接仍由 pg-pool 移除。
- 事务借出 Client 监听异步断连；断连阻止提交，坏连接销毁；ROLLBACK 失败不覆盖原始错误。
  不重放事务、不自动重提付费任务，Command 幂等、CAS 和归属校验保持。
- 项目列表使用一次 jsonb_to_record 提取七个摘要字段，保留原 JSON 值、排序、
  缺省值与用户/软删除过滤，不使用完整工程作为 API 响应。仍需单份大文档的解析内存，
  不是数据库任意负载下不再 OOM 的保证。
- 云服务不可用提示不再要求启动本地终端；失败保留已有列表，提供显式重试，加载期间禁用按钮。

## 验证

Server 全量回归 23 项通过，新增连接故障注入回归（不连接生产数据库）；
真实页面刷新函数回归与 Web typecheck 通过。
Repository PGlite 回归校验所有摘要字段与旧行为一致、跨用户隔离、缺省值、
大文档无损加载以及列表 SQL 单次提取。
修复后的摘要 SQL 在 A100 用 READ ONLY 事务验证：12 个项目，281 ms，返回 6071 字节；
未执行原高风险查询作对照，不把单次成功表述为长期稳定性证明。
