# 正交投影回贴方向修复

主模块 M06，协作 M07；算法 `PROJECTION-CAMERA-DIRECTION/1.0.0`。

近距离正交截图回贴时，原着色器用相机位置到表面点的透视方向计算朝向、覆盖和质量。画面边缘可见表面因此被误判为掠射面。用户车辆的捕获蒙版完整；模型射线取样中左侧表面朝向从错误的 0.099 变为正交方向的 0.779，另一处从 0.203 变为 0.817。

通过捕获投影矩阵的齐次行识别正交投影，视空间使用固定 +Z，世界空间使用捕获视图矩阵的逆旋转方向。透视相机保留原点到相机方向。共享 GLSL 覆盖单层、普通叠层、紧凑纹理数组、预览合成和 GPU UV 烘焙；CPU UV 栅格同步方向判定。纹理数组 Worker 只搬运纹理，不执行朝向判定；导出复用烘焙路径。

不调整深度遮挡、法线容差、0.90 可靠度阈值、蒙版、分辨率或背面保护。无数据/Schema/Command/CAS 迁移；现有图层重新构建材质后生效，无需重新生成。回滚代码恢复旧方向计算。

验证：用户模型和实际捕获相机离线射线取样；真实 WebGL2 编译并执行共享 GLSL，正交视/世界方向与透视方向分别符合预期（RGBA 255,115,255,255）；Web 类型检查、投影图层回归通过。尚未部署，也未在用户在线项目上替换材质。

发布构建：共享方向函数加入多个 shader 模板后，总 JS 为 3,269,323 bytes（原 3,267,927）；总预算增加 1,300 至 3,269,800，烘焙 chunk 预算增加 1,300 至 716,300，保留门禁及发布元数据余量；其他预算不变。
