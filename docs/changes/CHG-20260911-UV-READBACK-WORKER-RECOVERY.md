# UV 读回 Worker 启动与恢复

日期：2026-09-11。主模块 M07（UV 合成与发布），协作 M06（视口发布）、M04（多视图呈现交接）、M15（构建）。算法/协议标识：`UV-READBACK-WORKER-BOOTSTRAP/1`。

## 问题和证据

用户截图为白模及 `GPU readback conversion worker failed.`；随后多视图提示纹理已保存、视口未完成显示并停止后续视角。前者来自 Worker 的 error 事件且浏览器没有 message，后者是等待新图层实际呈现超时的保护，不是图片资产未保存的证据。

旧实现创建 Worker 后立即转移 GPU 像素。启动失败会丢失调用方对输入的所有权；构造或 postMessage 抛错没有清理 pending；error 回调引用全局 Worker，旧实例迟到的错误可能终止新实例。发布更新期间独立 Worker 文件可能不可用，但本次没有取得用户原始网络/崩溃日志，不能断言截图一定由 404 或内存耗尽造成。

## 修复边界

- 小型无 import 的转换内核使用 Vite inline Worker，生产页面已经加载模块后无需另取一个懒加载的哈希 Worker 文件。仍在 Worker 执行，不搬回主线程。
- Worker 安装处理器后发送 ready。启动确认前不复制或转移完整像素。并发请求共享启动；启动失败最多再试一次，单次启动超时 5 秒。持久故障明确失败，不无限转圈。
- 每个 Worker 独立管理请求和失效状态。同步发送失败移除自身请求；运行期 error/messageerror 拒绝所有在途请求、释放该实例。旧实例的迟到事件不会影响替代实例。
- 输入已经转移后的转换故障不自动重放。保留原上层失败处理和多视图呈现门禁，不以“已保存”冒充“已显示”，不擅自重启付费生成。
- 另一个未发布的 R8 内部质量缓冲优化已另存补丁并从此次修复移出，避免混合问题。

## 对等路径审计

GPU 光栅、读回条带、CPU 舍入/对照、Worker 的 RGBA 翻转及 unpremultiply/coverage/quality 公式、shader、Top-K、补边/接缝和深灰斜线不改。final/layer/resident/quality 全部入口共用新的启动生命周期。持久 RGBA、派生缓存键、Project Command/CAS/ownership/verified assets 和导出 PNG/FBX 不改。没有增加 CPU 回退，没有降低分辨率或删除 QA。

inline Worker 的生产启动需要浏览器允许 blob Worker；仓库没有发现主应用禁止 blob Worker 的 CSP。构建产物在内置 Chromium 浏览器中实际启动通过；不同外部 CSP/浏览器策略或浏览器进程 OOM 仍可失败，此时必须显示具体阶段而非假成功。

## 验证

- 完整前端回归 121 项通过，包含本次生命周期用例；两个改动源码的 ESLint、TypeScript 和本地生产构建通过。

- 生命周期回归：并发启动、启动失败保留原输入、共享一次重试、构造异常、超时上限、发送失败、转换崩溃/messageerror、旧错误隔离、请求级失败后的复用。纳入 `test:uv-source-scheduling`。
- Vite 生产构建的内置浏览器夹具：首次请求故意返回 404，第二次使用内联 blob Worker 成功；完整 resident RGBA/coverage/count 和 packed quality 为 4096²，layer/final 两种 alpha/非 packed quality 为 257²，全部逐像素对照一致，未捕获页面错误。测试计算及像素扫描耗时不是 Worker 性能指标。
- 当前割草机器人工程已变化为 6 个投影图层。真实 React 开关三层、快速切换、恢复原显隐、保存和 F5 完成，未捕获 Worker/页面错误；新组合约 1.05–1.15 秒，缓存恢复 31–32ms，F5 约 2.06 秒，首次加载 4.21 秒。它们不与之前 2 层/20 层对照，不声明已经即时更新。此处计时终点是现有 UV 发布/绑定确认，不是显示器呈现时间。
- 页面快照包含当前工程、4K、Saved、六个图层和测试完成提示；本次未取得新截图，因此不对接缝外观作新的视觉验收声明。真实付费多视图后续生成未主动重启。

## 迁移与回滚

无资产或 Schema 迁移，不重写历史工程。回滚本次 Worker 导入/生命周期及 ready 通知即可恢复旧逻辑，但会重新引入启动与资源失效风险。旧页面需加载新前端模块才能使用修复；不强制刷新用户正在生成的页面。

发布前运行全部前端回归、提交最终版本后执行 `pnpm verify:prepush`；沿用原包体门禁，不提高预算。正式检查会生成 Cloud 产物，本地调试产物需另行恢复。远端流水线结果与本地通过分开记录。
