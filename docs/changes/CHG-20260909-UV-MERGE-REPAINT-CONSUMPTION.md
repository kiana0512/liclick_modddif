# 合并图层后局部重绘：源图层消费与空白区域预览

主模块 M05/M07，协作 M06/M08/M12。维护版本 2.19.12。
算法/交互契约：UV-MERGE-SOURCE-CONSUMPTION v1.0.0、UV-MERGE-EMPTY-PREVIEW v1.0.0、UV-MERGE-RASTER-PARITY v1.0.0。

## 证据和范围

- 用户确认“删除参与合并的原图层，保留合并 UV 结果”。原 store 仅隐藏来源；重绘 sessionLayer 的恢复路径可重新显示同 generation 的旧结果，造成合并内容被重复应用。
- 用户两段录像：在中部控制面板回贴后，顶部/脚部未覆盖位置由斜纹变白；关闭局部重绘层又恢复。普通投影绑定在实时 overlay 持有显示权时可被静音，原 shader 的空白诊断只检查 projected visible，未计入仍可见的合并 UV。
- 用户随后提供的返回图中，控制面板已经被生成成上方栏杆。该内容错误已在返回图存在，不属于本次修复可纠正的投影坐标问题。未更改生成提示词、返图或模型几何。
- 第三段清晰录像 20260909215437（15.6 秒）使用另一张正确去除控制面板的返回图：涂画中旧文字/控制面板透出并有密集纹路，开关图层后恢复正确回贴。真实生产材质 + 4x MSAA 对照复现：UV 底图依赖固定管线逐采样深度，而 live 重绘显式写逐片元深度；斜面在同位置深度测试时交错通过。

## 实施

1. engine/layers 纯 helper 计算消费集：仅本次输入、同对象来源；保留 targetUvLayerId。重绘配对的 draft/overlay 仅在没有剩余结果引用时一起移除。未选中图层、其他对象、隐藏图层状态不改。
2. 既有合并流程仍先全分辨率烘焙、编码、验证资产和准备预览，成功后同一次 store 更新移除来源并插入/更新合并 UV。失败/取消不会提前删除原图层。
3. 被消费会话失效时同步清除 source、renderer preview、激活请求、工具和选择蒙版，并递增异步工具请求 revision。保留 generation 记录与所有历史资产，不进行物理删除。
4. 单层和生成整栈 shader 的空白诊断，取 projected 诊断与有效 UV 可见性中的最大值；常驻 texture opacity 更新、整栈重建共用同一判据，关闭 UV 后不留下诊断色。透明重绘 overlay 的独立早返回、真实 alpha/颜色合成公式不改。
5. UV-only 底图显式写入 gl_FragCoord.z，与实时重绘接受区域保持相同几何深度及采样方式。继续开启 depthTest，不加向前偏移、不移动模型、不关闭抗锯齿、不降低图像质量。合并后和合并前的投影栈都能使用相同深度规则。复用既有会话清理 callback，GLSL 重复说明迁到 TS 注释，避免扩大发布体积门禁。

## 一致性审计

- GPU/shader：调整未覆盖区域诊断和 UV-only 的当前相机深度写入；单层、非紧凑/紧凑整栈共享诊断函数，UV sampler 未启用的变体不引用缺失 uniform。动态 UV opacity 直接驱动判据。回贴几何深度/前景遮挡不放宽。
- CPU/Worker/烘焙/导出：不变。斜纹诊断从来不是导出材质；不将诊断画入 UV、不改作者蒙版/深度/source alpha/内缩/分辨率。
- 持久化：仍通过现有 setProjectLayers 和历史快照链路，不变更 Project Command、Revision CAS、ownership 或资产验证。来源只是从当前列表移除，撤销可还原；不主动清空历史。
- 无 Schema 或旧资产迁移；已隐藏的历史来源不做全工程扫描删除，只处理本次成功合并。
