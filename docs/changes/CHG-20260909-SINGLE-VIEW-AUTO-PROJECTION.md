# 单视图完成后可靠自动投影

- 主模块：M04；协作：M05/M06/M12。
- 生命周期契约：SINGLE-VIEW-AUTO-PROJECTION v1.0.0；维护版本 2.19.10。
- 问题：正常提交函数有自动投影，但后台 poll/reconcile 的成功分支仅同步生成记录。刷新、重新打开工程后不再有原提交调用栈，图片完成不必然进入图层。正常路径两次回贴失败后也缺少后续恢复。

## 实施边界

1. 面板按项目每 5 秒、online/focus 检查全部成功但未提交的单视图 texture-map 记录，不依赖当前页签、选中预览或参考图。活动生成/输入准备期间让原流程处理。
2. 全部入口使用原串行资产持久化→投影图层→工程 CAS 保存路径。缺少原 capture 时明确提示，不使用当前相机替代。上传失败保留结果并在下一轮重试，不调用生图 API，不改变输出分辨率。
3. 投影回执 projectedLayerId / projectionCommittedAt 在添加图层后、工程保存前写入 Generation。重复完成幂等，已消费结果被删除后不自动重建；在上传期间另一挂载已提交时保留其图层、橡皮和可见性。
4. 项目切换与取消在排队/解码/资产上传后的交接边界检查。未全部回贴不再使用成功文案掩盖失败。

## 一致性、兼容与回滚

GPU/CPU/Worker/shader 投影公式、capture mask/depth、透明边缘处理、UV 合成与导出不变，仍由原 Layer 驱动。原 Project Command 幂等性、Revision CAS、ownership、verified assets 保存路径保持。只复用已有 Generation.metadata 字段，无 Schema 升级、历史图片重算或资产迁移。缺少回执的旧单视图成功记录按待回贴处理；已有回执的历史删除保持。

回滚：恢复 GeneratePanel 的恢复调度与提交回执交接，移除新增策略模块；已有 Layer/Generation 继续可读，不删除资产。

新增测试直接执行生产事务函数和恢复回调，验证全部历史成功结果、重复/并发完成、上传失败再恢复、原相机绑定、取消、切换项目和已删除不复活。未调用付费生图服务；真实 A100 工程生图验收不包含在本地测试中。

101 项 Web 回归、TypeScript 和修改文件 lint 通过；Cloud 前端生产构建通过。新增恢复/提交保护候选包体 3,150,063 bytes，超过原总量门禁 1,313 bytes；已告知维护者，总量预算增加 2,000 bytes 至 3,150,750，单 chunk 限制与全部质量检查保持。本次仅本地修改，未推送 master 或部署 A100。
