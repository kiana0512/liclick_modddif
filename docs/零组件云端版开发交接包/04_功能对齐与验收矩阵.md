# 04 功能对齐与验收矩阵

## 1. 对齐的定义

原版功能迁移完成必须同时满足：

1. UI 入口、流程、提示和历史恢复与原版语义一致；
2. Web 请求字段、超时、取消、重试和路由正常；
3. Li3D API 验证登录、ownership、revision 和幂等；
4. 正式功能连接真实独立服务，不返回模拟结果；
5. 项目、资产和历史刷新/重登后可恢复并与账号隔离；
6. 自动化回归和真实浏览器至少各有一份证据。

页面能打开或按钮能点击不代表完成。

## 5. 每次发布人工冒烟

1. 干净浏览器打开 `/li3d/`，登录/退出/重新登录。
2. 新建文件夹和贴图项目，确认新人引导第一步出现。
3. 上传模型和单/多视图参考图，保存并刷新。
4. 生图、取消、恢复历史；局部重绘、应用结果、刷新恢复图层。
5. 提交正式 UV 和拓扑，检查真实 Worker、进度、失败原因、历史和产物。
6. UV/拓扑结果传入烘焙，检查高低模和贴图素材。
7. 执行 1K/2K/4K 代表性烘焙，查看/下载各通道和 ZIP。
8. 切换账号验证项目、资产、Job 和历史不可互见。
9. 检查浏览器 console/network：无本地组件警告、localhost 请求、chunk 404 和未处理异常。
10. 停启服务后复验 Session 策略、项目、对象资产和任务历史。

## 6. 不得伪造的状态

- 独立服务不可达时显示明确失败或排队，不显示“本机运行成功”。
- QA 拒绝的 UV/拓扑不能发布为可交付模型。
- 高低模未对齐不能显示为已对齐或已完成烘焙。
- 浏览器测试内核成功不能替代正式 Worker 验收。
- 模拟 OAuth 通过不能替代生产 HTTPS OAuth 回调验收。
