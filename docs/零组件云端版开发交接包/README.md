## 1. 交接目标

本交接包用于把 Li3D 从“网页 + 用户额外安装的 Windows 本地组件”迁移到“零安装浏览器 + 云端应用服务 + 独立计算服务”的实现交给后续开发团队。

这里的“纯服务器版”不表示把所有图形计算都压到 Li3D 应用服务器：

- 页面、项目数据、登录、历史和任务编排由服务器提供；
- 视口渲染、交互、图层合成、蒙版和适合浏览器的内核使用每位用户浏览器所在设备的 CPU/GPU；
- 正式 Auto UV、自动拓扑、Substance 烘焙、AIGC 生图和局部重绘调用独立服务集群；
- 用户不下载、不安装、不启动 Li3D 本地组件，也不连接 `localhost`/loopback bridge。

## 3. 当前结论

- 零组件 Cloud 产物边界已建立：不包含安装器、Windows 可执行文件、4618 本地桥接或 localhost 回退。
- A100 联调地址已由 systemd 托管，具备开机启动、异常重启、readiness、release manifest 和优雅退出。
- 真实员工登录、项目/文件夹、模型与参考图、项目 Revision、账号历史、正式 UV 小模型、正式 Substance 烘焙、AIGC 生图、局部重绘和旧 UV 历史传入烘焙已有真实纵向证据。
- 自动拓扑和大型生产模型 UV 已接真实服务，但历史实测仍出现质量门禁拒绝，不能宣称全部生产资产通过。
- PS/DCC 实时交互按产品要求暂缓，不允许因此重新引入本地组件。
- 当前是稳定候选和真实联调环境，不是已经完成生产容量、安全与多浏览器矩阵的正式版本。

## 5. 交接红线

1. 不修改或直接覆盖原始仓库；现代化工作继续在隔离目录和 `codex/modernization` 分支。
2. 不向 `main`/`master` 提交尚未完成生产验收的候选版。
3. 不恢复安装器、本地工作区、本地账号绑定、4618 或 `/api/comfyui/*`。
4. 不用 Mock、浏览器三角简化或本地测试内核冒充正式 UV/拓扑/烘焙成功。
5. 不删除 Revision、ownership、幂等和时间戳冲突门禁来“解决”409。
6. 不把 Secret、Cookie、CA 私钥、对象存储口令或数据库密码提交到 Git 和文档。
7. 不在没有备份和目标确认的情况下清理 A100 共享磁盘数据。
