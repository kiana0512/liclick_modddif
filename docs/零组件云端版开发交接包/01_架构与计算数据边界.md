# 01 架构与计算、数据边界

## 1. 目标拓扑

```text
用户浏览器（每位用户自己的设备）
  ├─ React / Vite UI
  ├─ Three.js / React Three Fiber 视口
  ├─ WebGL2 / WebGPU / ANGLE -> 用户设备 D3D11/D3D12
  ├─ Web Worker / WASM -> 用户设备 CPU
  └─ 同源 HTTPS API
           │
           ▼
Li3D 应用服务器（控制面）
  ├─ 飞书/莉刻/IDaaS OAuth 与 HttpOnly Session
  ├─ tenant/user/project ownership
  ├─ Project Command + Revision
  ├─ 文件夹、项目、账号历史与审计
  ├─ PostgreSQL 元数据
  ├─ 对象存储签名直传与下载授权
  └─ 真实计算服务编排
           │
           ▼
独立 GPU/AIGC API 集群（计算面）
  ├─ Asset V4 Auto UV
  ├─ Asset V4 Retopology
  ├─ Substance Baker
  ├─ Liclick 图像生成
  └─ ModelView 局部重绘
```

Li3D 应用服务器和 GPU/AIGC 集群是两个安全与扩缩容边界。计算 Worker 不拥有 Li3D 浏览器 Session，Li3D 应用服务器也不能伪造 Worker 产物。

## 2. 浏览器本地算力

浏览器执行以下能力，因此 100 个用户的逐帧渲染不会集中到 Li3D Node 服务：

- 3D 视口、相机、变换、材质和光照；
- 图层可见性、投影预览、蒙版绘制、局部选择；
- 图层合成、部分图片编码和边缘处理；
- Engine Session 管理的 GPU/CPU/IO lane、取消和资源释放；
- 浏览器安全范围内的 Worker/WASM/WebGPU 测试内核。

Windows Chromium 通常通过 ANGLE 把 WebGL 翻译为用户设备的 D3D11/D3D12。不能在业务代码中假设固定使用 D3D；最终后端由浏览器、系统、驱动和黑名单共同选择。验收时应记录浏览器 renderer 字符串，而不是仅写“支持 D3D”。

## 3. 必须走真实服务的能力

| 功能 | 正式执行位置 | 禁止替代 |
| --- | --- | --- |
| Auto UV | Asset V4 UV Worker | 浏览器 xatlas 不得作为产品默认成功路径 |
| 自动拓扑 | Asset V4 Retopology Worker | 本地三角简化不得冒充拓扑服务 |
| PBR 烘焙 | Substance Worker | 浏览器 BVH Bake 仅可用于隔离回归 |
| 生图/多视图 | Liclick AIGC | Mock/固定图不得标为成功 |
| 局部重绘 | ModelView/Liclick 服务 | 只在浏览器涂蒙版不代表云端任务完成 |

历史浏览器内核可以保留在测试代码中，用于验证通道语义和故障降级，但生产模式必须关闭服务端假成功与本地算法替代。

## 4. 数据权威位置

| 数据 | 权威位置 | 浏览器角色 |
| --- | --- | --- |
| 用户身份与会话 | Li3D Server + OAuth/IDaaS | 只持有 HttpOnly Cookie，不保存服务 Secret |
| 项目快照与 Revision | PostgreSQL/Project Repository | 缓存当前状态并通过版本化命令保存 |
| 模型、图片、贴图产物 | 对象存储 | 使用签名 URL 直传/下载 |
| UV/拓扑/Bake 历史 | 账号级服务器记录 | 查询、展示、恢复和交接 |
| 临时 GPU 资源 | 用户浏览器 | 页面/项目切换时释放，不是持久化数据 |
| 任务运行状态 | Li3D 任务记录 + 独立服务 | 轮询、取消和历史恢复 |

IndexedDB、OPFS、内存和 Zustand 不是项目权威数据，不能让刷新、换设备或切换账号依赖它们恢复服务器项目。

## 5. 零组件的可验证定义

一个候选发布只有同时满足以下条件才是零组件版：

1. 干净电脑只使用现代浏览器即可打开、登录和工作；
2. Cloud 构建不包含安装器、`.exe`、本地服务启动脚本或组件下载入口；
3. 浏览器网络请求不访问 `localhost`、`127.0.0.1` 或历史 4618 端口；
4. 不出现“打开本地工作区”“本机账号绑定”等产品门禁；
5. 项目、资产和历史在服务器端按账号恢复；
6. 正式计算功能调用已登记的真实服务，并保留任务所有权与产物校验。

对应自动检查：`pnpm check:cloud-boundary`、`pnpm check:cloud-artifact` 和浏览器网络/控制台验收。

## 6. 代码地图

- `apps/web`：浏览器 UI、编辑器、引擎、Worker 和 API 客户端。
- `apps/server`：身份、项目、资产、历史和计算服务代理。
- `packages/contracts`：Release、Project、Command、Revision、Asset 和 Compute 契约。
- `apps/server/prisma/cloud.schema.prisma`：Cloud 数据模型蓝图。
- `quality/cloud-release-readiness.json`：机器可读发布闸门。
- `scripts/cloud-boundary-policy.json`：零组件产物边界。
- `integrations/photoshop-uxp`、`connectors/*`：历史/暂缓集成，不属于零组件核心运行时。

更完整设计见 [技术架构](../02_TECH_ARCHITECTURE.md) 和 [现代化总纲](../modernization/README.md)。
