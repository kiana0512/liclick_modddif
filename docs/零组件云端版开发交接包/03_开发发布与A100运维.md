## 2. 本地开发

```powershell

```

源码主服务默认端口 4518，Vite 默认 5173；部署端口由 `SERVER_PORT` 决定。历史 4618 已退役。

开发模式允许使用隔离模拟器验证失败恢复，但提交“真实功能已通过”必须附真实账号、真实服务、真实输入和真实产物证据。

## 4. Release Manifest

Web、Server、Contracts 和数据协议必须由同一 Git SHA 构建。构建注入：

- `LICLICK_RELEASE_ID`
- `LICLICK_GIT_SHA`
- `LICLICK_RELEASE_VERSION`
- `LICLICK_BUILD_TIME`
- 对应 `VITE_*`
- `LICLICK_RUNTIME_MODE=cloud`

运行后用 `/api/release` 核对，不允许前端和后端来自不同提交。

## 6. 安全发布顺序

1. 记录当前 `/api/release`、服务状态和备份路径。
2. 在 CI/开发机生成 Cloud 运行制品；服务器不执行现场 `git pull` 和依赖升级。
3. 校验制品 SHA-256。
4. 备份当前代码，明确排除并保留 `runtime/`。
5. 受控停止 systemd，替换代码制品，启动 systemd。
6. 检查 health、ready、release、首页、登录和旧 ComfyUI 404。
7. 真实浏览器验证项目、模型/参考图、保存刷新、新人引导和计算历史。
8. 异常时切回上一制品，不覆盖数据库和对象存储。

详细命令和 systemd 单元见 [A100 运维交接](../A100_SERVER_HANDOFF_2026-08-23.zh-CN.md)。

## 7. 环境变量分组

- Web/端口/公共路径/允许 Origin；
- OAuth/IDaaS/Session/Cookie；
- PostgreSQL Repository 和连接池；
- 对象存储 endpoint、bucket、签名 TTL 和凭据；
- Asset V4、Substance、Liclick、ModelView 地址与 CA；
- API 并发、请求超时和优雅退出预算。

环境文件权限应为 0600。配置变更必须记录变量名、用途、是否必需和轮换步骤，但不记录 Secret 值。

## 8. 健康与排障

```bash
curl -fsS http://127.0.0.1:44770/li3d/api/health
curl -fsS http://127.0.0.1:44770/li3d/api/ready
curl -fsS http://127.0.0.1:44770/li3d/api/release
curl -i http://127.0.0.1:44770/li3d/api/comfyui/status
sudo systemctl status li3d-modernization.service --no-pager --full
sudo journalctl -u li3d-modernization.service -n 200 --no-pager
```

常见故障顺序：先确认端口和 systemd，再核对 release/chunk，随后检查登录 Cookie、项目 revision、对象存储和独立计算服务。不要把所有失败都归因于 GPU 服务。
