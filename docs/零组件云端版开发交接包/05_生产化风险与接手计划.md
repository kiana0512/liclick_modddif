# 05 生产化风险与接手计划

## 1. 当前发布等级

当前版本是“真实 A100 联调稳定候选”，不是正式生产完成版。功能主干已经形成，但正式上线仍缺容量、安全、灾备和生产资产矩阵。

## 2. P0：正式上线前必须完成

1. **HTTPS 与 OAuth**：正式域名、企业应用发布、精确回调白名单、Secure/SameSite Cookie 和退出吊销。
2. **数据灾备**：PostgreSQL 备份/PITR、对象存储版本/生命周期、恢复演练和删除审计。
3. **容量治理**：A100 根分区此前达到约 95%，设置告警、明确数据 owner、清理/扩容；应用脚本不得擅自删共享数据。
4. **网关保护**：上传大小、账号/IP 限流、任务配额、并发、超时、熔断和下游隔离。
5. **100 用户压测**：30～60 分钟混合项目保存、资产上传、历史、生成、UV 和烘焙；记录 P50/P95/P99、错误率、DB 池、对象存储和队列积压。
6. **多实例一致性**：多副本 Session、Command 幂等、任务 ownership、分布式锁和优雅滚动发布。
7. **原子发布**：`releases/<id>` + `current` 或容器镜像，不再直接替换运行目录；自动 readiness 回滚。

## 3. P1：功能质量收尾

- 大型工业模型 Auto UV 的 `UV_QA_FAILED` 定位和生产资产矩阵。
- 自动拓扑坐标恢复与 `RETOPOLOGY_COORDINATE_MISMATCH` 修复。
- 贴图工作台完整图层、撤销、导出和像素金图回归。
- 局部重绘生产模型遮挡、接缝、边缘和跨会话结果恢复。
- Substance 更多模型、通道组合、取消/失败/恢复/4K 压力矩阵。
- Chrome/Edge/Firefox、Windows GPU/驱动、WebGL/WebGPU 和设备丢失矩阵。
- 所有用户可见错误信息统一中文，并带 request/job correlation ID。

## 4. P2：架构债务

- 拆分 `ViewportCanvas.tsx`、`SceneRoot.tsx`、`EditorPage.tsx`、`GeneratePanel.tsx` 的职责。
- 扩大 Engine Session 对 GPU/Worker/缓存资源的统一登记和释放。
- 把历史文件型开发存储全部收口到生产 Repository，禁止长期双写。
- 统一 API client 的取消、超时、409 重放和错误码映射。
- 补充 OpenAPI/JSON Schema 自动生成；当前 contracts 是协议真源但尚无完整公开 API 文档生成链。
- 继续清理命名仍含 `local` 但已不代表本地组件的兼容代码，避免开发误解。

## 5. 建议接手节奏

### 第 1 天：复现基线

- 拉取 `codex/modernization`，执行全部门禁。
- 阅读本交接包和 12 个 ADR。
- 在 A100 只读核对 release、systemd、环境变量名和日志。
- 完成一遍真实浏览器冒烟，不修改生产数据。

### 第 2～3 天：契约和运维补齐

- 生成 API 清单/OpenAPI 草案。
- 给关键请求补 correlation ID、指标和告警。
- 建立原子制品发布与自动回滚方案。
- 规划正式域名 OAuth 和 Secret 轮换。

### 第 4～5 天：生产门禁

- 建立 100 用户混合压测脚本和测试账号。
- 完成数据库/对象存储恢复演练设计。
- 用三类生产模型跑 UV、拓扑、Bake 质量矩阵。
- 输出是否可灰度、阻断项 owner 和时间表。

## 6. Definition of Done

正式发布至少要求：

- 零安装边界、功能回归、服务回归、contracts、类型、lint、构建全部绿色；
- 正式域名真实登录、账号切换和越权矩阵通过；
- 100 用户负载达到约定 SLO，无项目串号、Revision 丢失和任务越权；
- PostgreSQL/对象存储备份恢复演练通过；
- UV、拓扑、Bake、AIGC 用代表性生产资产成功且产物经 QA；
- 原子发布、readiness、优雅退出和自动回滚通过；
- 监控、告警、日志和事故处理文档齐全；
- 产品、开发、测试和运维共同签署验收。
