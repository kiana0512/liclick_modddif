更新时间：2026-08-17

## 1. 一句话总结

今天集中修复了 UV 合成彩虹纹与闪屏、局部重绘透明区被画成黑块、刷新后白膜、图层眼睛全关后无法重新显示纹理、PBR 滑条错误恢复纹理、GLB 导出贴图方向错误，以及投影视图之间的黑色细缝；同时隐藏了尚不稳定的模型表面橡皮擦入口，并为重复 UV 合成和内容识别修补增加了有边界的会话内缓存。

这轮优化以稳定性和质量为第一优先级。重复操作有可测提速，但 F5 后的冷启动仍走完整安全链路，因此用户体感可能只有小幅改善，不能把它描述为冷启动的大幅提速。

## 3. 用户可见问题与修复结果

### 3.1 UV 合成彩虹纹和浏览器闪屏

- UV 合成回到经过验证的质量合成路径，删除会改变颜色或接缝结果的激进后处理分支。
- GPU readback、质量混合和 Worker 结果保持 straight RGBA 语义，避免错误的 Alpha/颜色解释产生彩虹纹。
- 材质替换和投影显示采用“新资源 ready 后原子发布”，避免先卸载旧材质再异步等待新材质造成闪屏或白膜。
- 失败时保留最后一份有效纹理，不把半成品发布到模型。

### 3.2 局部重绘黑色外轮廓

- 回贴只使用真正有效的 Alpha/蒙版区域。
- 透明背景中的黑色 RGB 不再被当成模型颜色。
- falloff 在 Worker 中计算，并保留被保护区域，避免边缘黑块和主线程长任务。

### 3.3 F5 后回到白膜

- 项目恢复过程增加请求修订号，过期的异步模型加载不能覆盖新状态。
- 已恢复的模型可直接复用，避免 App 和编辑器重复导入同一模型。
- 模型、图层和材质恢复按项目身份隔离；切换项目会中止旧恢复链路。

### 3.4 全关眼睛后无法重新显示纹理

- 全关图层时明确显示白膜，这是预期状态。
- 从白膜状态重新打开任意有效 UV 或投影层时，如果模型上还没有可接收 uniform 的投影材质，只触发一次材质协调。
- 正常眼睛切换仍走已有的 uniform 快路径，不引入每次点击重建 shader 的性能回退。
- PBR 曝光、强度、环境亮度和灯光角度只更新显示参数，不再绕过图层可见性恢复纹理。

### 3.5 GLB 导出贴图方向

- Li3D 图集使用左上角 Canvas 坐标；GLTFExporter 输出时开启纹理 `flipY`，使导入 Blender 等 DCC 后与 Li3D 视口方向一致。
- 新增导出方向回归脚本，避免再次出现“Li3D 正常、DCC 上下颠倒”。

### 3.6 投影交界黑缝和内容识别修补

- 缝隙识别与可见的 hatch/空洞阈值对齐，保留 1 像素细缝，不再因为形态学过滤而漏掉。
- 一次 O(N) 传播可以覆盖完整可达区域，不再受固定迭代次数限制。
- 对同一拓扑内没有局部 donor 的断开区域，使用全局有效 donor 的平均颜色兜底；兜底仍受 `writeMask`、拓扑和区域约束，不会覆盖已有贴图。
- 目标是消除明显黑洞和黑色条纹，不承诺对大面积缺失区域进行审美级纹理生成。

## 4. 性能与缓存策略

### 4.1 保留的缓存

`EditorPage.tsx` 保留一个会话内 `Map`，最多两个条目：

1. `merge-uv`：最多一份 4K straight RGBA 投影合成，约 64 MiB；
2. `content-aware-repair`：最多一份 2K straight RGBA 投影合成，约 16 MiB。

缓存命中必须同时满足项目、对象、模型矩阵、分辨率、图层顺序、可见性、透明度、混合参数、资源 URL、内容 revision、烘焙选项和调试选项完全一致。读取时先复制 `ImageData`，后续 UV underlay 合成不能污染缓存原件。

缓存会在切换项目、身份变化和页面卸载时清空；不会写入项目、LocalStorage、IndexedDB 或磁盘。F5 后故意不复用，避免运行时深度/法线与新 WebGL 上下文不一致再次引发闪屏和白膜。

### 4.2 缓存审计结论

- 局部重绘仍有一处 `Map<URL, Promise<URL>>`。该逻辑目前只是复用已 resolve 的 URL，没有执行下载、解码或转换，实际提速价值很低，并且没有容量上限。
- 为避免在本轮稳定性修复后追加代码改动，本次只记录该审计项，不随交接文档修改运行时代码；后续可单独删除该 Map 和对应的无效预热 `useEffect`。
- 保留两项有边界的投影烘焙缓存；它们是重复操作提速的来源，不属于垃圾缓存。

### 4.3 已测数据与解释

在本机 Li3D 性能实验室的同一会话重复操作中：

- 内容识别修补热路径约 `50.98 s → 0.415 s`；
- 4K UV 合成热路径约 `45.0 s → 8.49 s`；
- 热路径交互样本约 `P95 16.8 ms`、最大帧 `16.9 ms`、掉帧 `0%`。

这些数字只代表缓存命中的重复操作。首次打开、F5 后和任何图层/模型变化都会缓存 miss，并走完整质量链路；冷路径的主要耗时仍是深度生成、GPU 投影栅格、4K 合成和 PNG 编码。因此当前“体感只快一点”是合理反馈，后续不能以持久化运行时纹理来冒险换速度。

## 5. 橡皮擦状态

- 模型表面的独立橡皮擦按钮和快捷入口已隐藏。
- 如果旧会话残留 `paintTool = eraser`，底部工具栏会立即复位到 `none`，避免隐藏功能继续运行。
- 局部重绘弹窗和图像编辑器内部各自的擦除工具不受影响，它们属于不同工作流。
- 底层表面橡皮擦实验代码暂时保留但不可从正式 UI 进入；不建议在本次合并中继续扩大删除范围，因为它与共享投影 shader、绘制历史和笔输入代码交织，机械删除容易制造显示回归。后续若正式废弃，应单独提交并做 shader/历史/触控回归。

### 7.2 真实项目回归

1. 打开 14 个投影视角的真实项目，确认初始纹理正常，无全屏异色闪烁。
2. 全关投影层和 UV 层，保存并 F5；模型应为白膜。
3. 逐一重新打开投影层和合并 UV 层；纹理应立即恢复，眼睛按钮与模型一致。
4. 全关图层时拖动四条 PBR 滑杆；模型必须继续保持白膜。
5. 连续切换 PBR、平面、法线、线框；不能出现旧纹理抢回、闪屏或永久白膜。
6. 执行 4K UV 合成，检查彩虹纹、上下方向、透明 gutter 和接缝。
7. 执行内容识别修补，重点观察薄片、齿轮间、槽体和 UV 岛边缘的黑缝。
8. 导出 GLB，在 Blender 或同等 DCC 中确认纹理方向与 Li3D 一致。
9. 开启 `?perfLab=1`，全过程观察 P95、最大帧和掉帧；操作期间不允许出现持续卡顿或明显掉帧。

## 8. 已知限制与禁止回退项

- 冷路径仍偏慢，本轮没有安全地解决 F5 后的深度重建和首次 4K 上传耗时。
- 4K PNG 编码及首次 GPU 上传仍可能产生长帧，后续应独立优化，不应把半成品纹理提前发布。
- 内容识别修补上限为 2K，定位是遮住明显黑缝，不是生成高质量新纹理。
- 禁止重新持久化投影层运行时 `normalUrl` 或直接复用旧 WebGL 纹理；该方案已实测导致纹理数组失败、模型闪动和全白膜。
- 禁止以降分辨率、少处理图层、跳过 Alpha/接缝校验或提前隐藏源投影层来换取表面速度。
