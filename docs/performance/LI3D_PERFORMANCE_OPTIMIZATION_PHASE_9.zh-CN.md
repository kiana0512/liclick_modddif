## 2. 不可变正确性约束

1. GPU UV 烘焙必须执行 `保存 DPR → DPR=1 烘焙 → 恢复 DPR`，不得删除或改写。
2. 视口 DPR 不得为了压测动态降低；本轮视口保持 1.25。
3. 内容填补算法、深度/法线判定、拓扑阈值、质量混合和覆盖规则不得改变。
4. 4K RGBA A/B 必须逐字节为 0；覆盖率必须为 48.41%。
5. 新纹理必须完全解码和上传后原子发布；禁止白膜、半成品和异步旧任务覆盖用户眼睛状态。

## 3. 已交付修正

### 3.1 DPR 不变条件下消除共享画布闪动根因

新增持久化隐藏 GPU 烘焙 renderer。烘焙 renderer 继续固定 DPR=1，但不再对 React Three Fiber 的可见 canvas 调用 `setPixelRatio()`。这隔离了 Three.js 因 DPR 切换而重设/清空可见 drawing buffer 的路径。

运行时深度仍使用正式视口 renderer，并在提交 readback 后立即恢复 render target、viewport、scissor、clear、XR 和材质状态；GPU UV 光栅使用隐藏 renderer。

### 3.2 内容修补、UV 合成、投影转 UV 原子发布

- 最终 PNG 在 Worker 编码，主线程只接收 URL 和标量元数据。
- 内容修补与 UV 层在图层 store 更新前完成解码和分片 GPU 上传。
- 旧图层保持显示，直到新纹理 ready 后一次切换。
- 发布边界重新读取最新图层状态，用户在后台任务期间修改的眼睛状态具有最高权威。
- 投影转 UV 预热失败时保留原投影层，不发布不完整 UV 层。

### 3.3 全关图层白膜修正

所有纹理层关闭时使用统一基础 `MeshStandardMaterial`/显示模式材质，不再走投影 shader 的白色占位采样，因此不会出现比初始材质更亮、轮廓被洗掉的白膜。

### 3.4 共享 renderer 状态隔离

离屏渲染完整保存/恢复 render target、viewport、scissor、clear、autoClear 和 XR。GPU UV 烘焙不再在图片加载、分条上传或异步回调期间把共享 renderer 留在 4K render target 上，避免地面异常亮线和中间帧污染。

### 3.5 重任务调度与即时反馈

- 4K UV 合成与内容识别修补进入统一串行调度器。
- 点击先在当前帧发布 UI 反馈，重任务下一绘制边界启动。
- 同类任务支持 latest-wins、取消和替换。
- 调度器记录 queued、started、milestone、first-result、completed/cancelled 时间线。

### 3.6 4K Worker URL 交接

- PNG RGBA、PNG 编码和 Blob URL 创建留在 Worker。
- 结果交接不再把 64MiB RGBA 结构化克隆回主线程。
- Worker 保持长期存活并负责 URL 生命周期，避免 Worker 退出后 URL 失效。
- 4K WebGPU RGBA 合成保持 8MiB 空闲分片、1MiB 交互分片和逐字节 CPU A/B。

| 指标 | 实测 |
| --- | ---: |
| 帧 P95 / 最大 | 16.8 / 467.1ms |
| 最慢阶段 | `uv-underlay-composite-encode` |
| GPU 链 | 36.390s |
| 运行时深度 | 6.142s |
| GPU 光栅/回读 | 13.952s |
| 质量混合 | 5.795s |
| 接缝 / 补洞 / Gutter | 2.003 / 5.768 / 2.530s |

## 10. 否决与回退记录

1. 删除 GPU DPR=1：导致 UV 内容大片错误留白，立即回退。DPR=1 已列为不可变约束。
2. 后台拓扑预热：为避免任何缓存条件差异，已从本轮交付移除。
3. 跳过权威 GPU Canvas/输入路径的实验：在用户报告效果变化后撤回。
4. 4K 清理 Worker 往返：64MiB 所有权回交未降低最大帧，已撤回。
5. 纯 Worker PNG：最大帧和总耗时回退，已撤回。
