## 二、第一部分：减少模型切换卡顿并修复选中边框回跳

提交名称：`优化：减少模型切换卡顿并修复选中边框回跳`  
模块：M03（场景、相机与捕获）、M08（局部重绘）。

### 2.1 发现的问题

1. 模型选择变化会让无关模型组件重新执行，并触发原本不需要的空白蒙版重置。
2. 选中边框与部分预热资源反复创建；相机在判断“不需要重新取景”之前已经遍历模型计算边界。
3. 边框显示可能依赖旧的 React 选择状态；另一路异步捕获结束后重复恢复旧显隐、材质快照，覆盖了用户刚刚作出的选择。
4. 图层面板虽然被 CSS 隐藏，缩略图处理仍可能在后台启动。普通图片的懒加载属性不能阻止自定义 Canvas 像素处理。
5. 局部生图提交与返图准备中的部分等待只使用 `requestAnimationFrame`；页面进入后台、停止派发渲染帧时，这些等待可能无法继续。

### 2.2 具体改动

| 改动 | 处理方式 | 用户可感知的作用 |
| --- | --- | --- |
| 减少无关模型更新 | 模型组件按自身“是否选中”订阅并复用；列表选择也登记为视口交互 | 减少切换时无关组件工作，让后台任务识别正在交互 |
| 避免空白蒙版反复清理 | 无作者蒙版、无活动重绘状态时不递增昂贵的蒙版重置版本 | 普通切换不再无条件清空、上传蒙版目标；有编辑状态时仍按原规则清理 |
| 复用选中框 | 保留各模型的小型边框 geometry/material，选择时切换显示；卸载时释放 | 减少反复创建、释放资源 |
| 修复边框回跳 | 每个呈现帧核对当前对象及工作区；捕获快照恢复器只执行一次 | 旧选择状态和迟到的捕获恢复不再把旧模型边框重新显示出来 |
| 延后无效预热 | 在交互空闲后再分配预热资源，各 GPU 阶段前复核模型和工具归属 | 切走后的任务不再无条件继续完整准备 |
| 相机边界按需计算 | 先判断是否需要取景，再遍历边界 | 场景内仅切换选择、不改变取景时减少遍历 |
| 隐藏缩略图停止启动处理 | 通过 IntersectionObserver 判断非零可见交集，再挂载像素预览消费者 | 隐藏、折叠、移出可见区域的缩略图不再启动新处理 |
| 后台等待兜底 | 非呈现证明的等待接入 `waitForBrowserPaint` / `scheduleAfterBrowserPaint` | 避免部分任务仅因后台没有 rAF 而悬挂 |

边界：该提交只阻止不可见缩略图启动新工作，尚未全面取消已经启动的共享预览；后者由第三部分继续处理。缺少 IntersectionObserver 时保留原可用性回退。

后台兜底不等于“后台强制持续渲染”。真实 GPU 呈现交接和画笔互斥仍保留；浏览器完全冻结或丢弃页面时，页面 JavaScript 仍不能保证执行。远端生成任务及页面恢复后的状态同步仍是任务恢复的基础。本次未改变服务端生成任务调度，也未完成付费生图全链路的后台冻结验收。

## 三、第二部分：修复 CI 发布包体超限

## 四、第三部分：串行调度贴图预览，减少快速切换卡顿

提交名称：`优化：串行调度贴图预览并减少模型切换卡顿`  
主模块：M08；覆盖生成、图层与面板呈现。`ALG-LR-011` 升级为 v1.1.0。

### 4.1 进一步定位到的问题

在贴图工作区快速切换模型时，长帧中出现多个图片加载回调，一次长帧内的回调分别达到约 46–56.7ms。构建位置对应 `urlToImageData` 的图像读取及其后续处理。

代码检查发现三条放大因素：旧预览即使不再显示，仍可能继续排队和计算；原 12 项缓存容易在多模型切换时淘汰；恢复另一模型的活动图层会自动展开图层面板，再次触发缩略图工作。此外，多视图模式没有结果预览卡时，生成面板仍可能准备不会显示的结果预览。

这些是代码和录制支持的处理路径，但长帧记录没有提供每次回调的完整业务调用栈，不能把所有卡顿全部归因于缩略图。

### 4.2 新的处理方式

1. **统一串行队列。** 生成显示副本和 capture-mask 显示预览共用队列，避免多个自定义预览处理同时推进。该队列不是全应用的图片或渲染队列。
2. **交互优先。** 前台沿用 180ms 交互安静窗口，按 32ms 定时检查是否可以启动；部分处理阶段之间再次检查交互与取消。后台不依赖 rAF 才能继续。
3. **按消费者取消。** 切模型、隐藏或卸载时释放该消费者；最后一个消费者退出后取消无人使用的排队任务，运行中任务在后续检查点停止，迟到结果不缓存、不发布。另一个面板仍在使用同一任务时不会被误取消。
4. **有界 LRU 缓存。** 完成结果按处理类型、源图、深度或蒙版及内容版本建立缓存键，命中后更新最近使用顺序；最多 64 项、32 MiB 编码字符串估算，不缓存解码后的 ImageData。超过容量时淘汰旧的完成结果，失败结果不进入缓存。
5. **隐藏结果不处理。** 多视图没有结果卡、生成面板隐藏或折叠时不启动显示预览；独立预览模态打开时仍可处理。不卸载生成任务和表单状态。
6. **保留折叠选择。** 恢复另一模型的图层不再强制展开图层面板；同模型显式选择另一图层仍保留原打开行为。
7. **防止旧内容回写。** 缩略图的缓存请求和显示匹配包含 `contentRevision`，避免同一 URL 内容更新后继续显示旧版本副本。

取消有明确边界：已经进入浏览器的图像解码不会被强制中断；这不是可抢占线程。32 MiB 只约束队列保存的编码字符串估算，不代表整个浏览器内存上限。本次也尚未把预览像素循环和 PNG 编码迁入 Worker。

### 4.3 实现位置

- 新增 `apps/web/src/engine/localRepaint/displayPreviewQueue.ts`：共享任务、交互门控、消费者取消、LRU 与容量管理。
- `apps/web/src/engine/localRepaint/resultPreviewUtils.ts`：显示预览接入队列与阶段检查；正式投影处理路径不接入该 UI 队列。

- 回退第三部分：恢复原预览调度/缓存和面板打开行为，无数据迁移。
- 回退第一部分：按问题拆分恢复选择框、预热、捕获恢复或后台等待路径；需重新验证边框回跳及后台悬挂风险。
- 第二部分仅清理不可达分支，通常应保留；恢复该分支可能再次超过包体门禁。相关提交在同一文件存在依赖，不能假定任意单条 revert 都可直接通过构建。
