## 2. 本地前端与交互修改

### 2.1 生成面板与工作区布局

- 重构“生成”面板的纵向排版，使预览、参考图、视角、提示词尽量在有限高度内完整展示。
- “对象”面板保持独立，不随生成面板滚动；最多按约 4 个模型的高度展示，超出后在对象列表内部滚动。
- 生成区域单独滚动，修复添加多张参考图后无法滚动到提示词输入框的问题，并隐藏视觉上突兀的滚动条。
- “生成纹理贴图”按钮固定吸附在画面视窗底部，不跟随生成面板内容滚动，也不再出现外围白色描边或与输入框重叠。
- 缩小纹理预览图和提示词输入框的垂直占用，保留预览、下载、图层等操作入口。
- “对象”和“生成”整体允许自然向下布局，不强制吸附页面顶部，减少面板底部的大块空白。
- 右侧“视口”和“图层”面板固定主要尺寸，切换 PBR、平面、法线、线框等显示模式时不再来回收缩。
- “图层调整”并入图层面板右上角工具栏，移除单独占位的调整窗口。
- 贴图工作区隐藏底部“选择工具”图标；场景类界面仍保留选择工具。

### 2.2 单视图、多视图与视角预设

- 生成模式改为清晰的“多视图 / 单视图”切换：
  - 单视图模式只展示单图预览、参考图和提示词，不展示多视图预设。
  - 多视图模式展示预设与全部模型方向视图。
- 预设从下拉框恢复为 3 个直接可见的模块：
  - 预设 1：10 视角；
  - 预设 2：14 视角；
  - 自定义预设：基础 6 视角。
- 在预设名称下增加视角数量提示，移除“前、后、左、右……”的长文本说明和各卡片上的方向文字。
- 视角卡片改为正方形、单层灰色圆角背景；移除选中高亮描边以及重复嵌套的第二层灰色背景。
- 所有视角直接展开显示，不再依赖响应迟缓的横向滚轮；“+”添加视角卡片固定在最后一个位置。
- 默认空视角和刷新后的预设恢复逻辑统一，避免前、后视图加载成错误占位或刷新后预设显示异常。

### 2.3 参考图工作流

- 参考素材由“参考图组”改为一张一张的独立参考图卡片，界面统一使用“参考图”命名。
- 参考图卡片移除文件名和厚重线框，采用更紧凑的缩略图排列。
- 鼠标移入图片右上角显示操作入口，菜单包含：
  1. 选中图片；
  2. 生成多视图；
  3. 预览图片；
  4. 复制新副本；
  5. 删除图片。
- 支持把图片直接拖入参考图区域，自动识别为参考图并上传。
- 单视图和多视图均可直接作为输入：
  - 只有单视图时，点击“生成纹理贴图”会先自动生成多视图，将结果写回参考图，再继续生成纹理；
  - 已有多视图时直接进入纹理生成；
  - 两者都没有时给出明确提示，不提交任务。
- 为单视图和多视图空状态增加默认示例素材：
  - `apps/web/public/examples/reference-single.png`
  - `apps/web/public/examples/reference-multiview.jpg`
- 多视图纹理流程末尾自动接入内容识别修补，用户侧只看到统一生成进度，不暴露内部投射、快照和补缝阶段。

### 2.4 纹理生成进度

- 生成按钮增加由暗到亮的进度渐变。
- 多视图补全、模型多视角快照、纹理生成和自动补缝合并到同一条用户进度中。
- 对外文案统一为“生成中”，避免把内部算法步骤暴露给用户。

## 3. 局部重绘前端流程

### 3.1 三步过程化工具

底部工具栏将局部重绘整理为一组连续流程，并与橡皮擦、撤销、重做等普通工具作视觉区分：

1. 绘制蒙版；
2. 局部生图；
3. 局部重绘画笔。

- 三个步骤使用不同图标，并通过小箭头表示执行顺序。
- “局部重绘”作为分组标题展示，不再看起来像一个可点击按钮。
- 左右分隔线长度统一，右侧分隔线改为与主题一致的粉色。
- 未绘制蒙版时，步骤 2、3 保持禁用；蒙版完成后仅步骤 2 可用；局部生图返回后步骤 3 才可用。
- 用户越级点击时显示流程提醒，而不是静默无响应。

### 3.2 蒙版与局部图片

- 蒙版绘制与擦除合并为同一工具：左键绘制蒙版，右键擦除蒙版。
- 在蒙版操作期间拦截浏览器右键菜单，避免右键擦除触发浏览器交互。
- “局部生图”从生成面板移到底部工具栏，位于蒙版绘制和局部重绘画笔之间。
- 初版曾把局部生图结果加入单视图参考图；合并远端算法后改为独立“重绘效果图”预览，避免把中间结果混入纹理生成参考输入。
- 进入局部重绘时自动创建并选中专用空白图层；退出后再次进入会继续使用该图层，只有重新生成局部结果时才建立新的重绘状态。

## 4. 首次创建项目引导

新增 `TextureOnboardingTour`，仅在用户第一次创建文件时显示：

- 整体画面覆盖半透明暗色蒙版，当前目标区域保持突出。
- 用户单击界面即可依次进入下一步，完成后恢复正常操作。
- 引导步骤与最终文案：
  1. **导入模型**：导入需要制作纹理的模型；
  2. **添加参考图**：上传单视图或多视图参考；
  3. **生成纹理**：点击即可生成贴图；
  4. **修改单视图**：切换到单视图，修改想要调整视角的纹理；
  5. **橡皮擦与局部重绘**：橡皮擦清理选中图层的纹理。局部修改按“蒙版 → 局部生图 → 重绘”使用。
- 第 4 阶段拆成两个定位弹窗，分别指向单视图区域和底部橡皮擦/局部重绘工具组。

## 5. 从远端 `master` 合入的性能优化

### 5.1 合成 UV GPU 驻留缓存

- `SceneRoot` 为完成的 UV 合成纹理建立容量为 3 的 LRU 显存缓存。
- UV/投影切换命中相同图层签名时直接复用完整 GPU 纹理，避免重复执行图片转换、Worker 合成和 GPU 上传。
- 采用延迟释放策略，避免纹理仍在采样时被销毁造成黑闪。

### 5.2 投影数组细粒度提交与 Shader 驻留

- 投影纹理数组按约 1 MiB RGBA 条带上传，每条提交前让出显示帧，减少拖拽旋转期间的主线程/GPU 队列竞争。
- 保留有限数量的不持纹理 ShaderMaterial 锚点，避免 0→14 层、UV/投影切换和测试栈恢复时重复编译相同 WebGL 程序。
- 增加显存分配、上传耗时、最大条带耗时、着色器编译和 yield 次数等性能埋点。

### 5.3 深度与法线任务调度

- 同一 WebGLRenderer 上的运行时深度/几何法线捕获进入严格串行队列。
- 避免多个视角异步读取和材质切换同时改写共享 R3F 上下文。
- 保持原有分辨率、深度编码、法线计算和 PNG 数据链路不变。

### 5.4 Worker WebGPU UV 拓扑光栅

- 新增：
  - `apps/web/src/engine/bake/webGpuUvTopologyRaster.ts`
  - `apps/web/src/workers/webGpuUvTopologyRaster.worker.ts`
- Worker 使用独立 WebGPU render pipeline，把 UV 三角形直接光栅到完整 4K `r8unorm` 纹理，避免占用主 R3F/WebGL 上下文。
- 首次模型/分辨率组合与 OffscreenCanvas 金标准逐像素校准；校准一致后缓存复用。
- WebGPU 不可用、设备丢失、Worker 异常或校准失败时，自动回退 Worker Canvas，再回退原主线程兼容路径。
- 保留 `?webGpuUvTopology=0` 显式关闭开关，便于兼容性回归。

### 5.5 图层混合模式常驻 GPU 状态

- Blend/Overlay 从投影材质结构签名中移出，切换混合模式不再重组投影数组或重新编译整套 Shader。
- 两种模式通过同一常驻 Shader 的互斥 uniform 切换，避免异步窗口中同时生效。
- 投影覆盖、Alpha、颜色、深度/法线判定和边缘羽化公式保持不变。

## 6. 从远端合入的局部重绘算法与显示修复

### 6.1 高清 GPU 前景通道

- 局部重绘颜色源与 Alpha 蒙版拆分为两张独立 GPU 资源。
- 颜色纹理直接使用生成结果原始分辨率，交互蒙版为 1024px，不再使用 512/288 低清代理。
- 局部结果作为独立 GPU 前景 sampler，不进入多层背景投影数组重打包。
- 混合语义改为“蒙版内直接替换”，区域外保持透明，不产生黑底、整图覆盖或 Overlay 对比度偏移。
- 缩略图和大图预览均应用真实 Alpha，大图使用棋盘格检查透明区域。

### 6.2 预热、首笔反馈与删除

- 浏览器直接解码原始资源地址，不再先转换完整 base64 data URL。
- 生成结果到达后后台完成纹理解码、颜色上传、Alpha 上传和材质预编译；资源 ready 前保留最后一个有效材质，避免短暂白膜。
- 去掉固定 5 秒等待和超时重启预热；实际准备完成后立即发布 ready。
- 按钮 3 只原子切换已经预热的 GPU 前景，未完成时复用当前任务，不重复解码。
- 删除局部重绘层时先同步关闭运行时 GPU 可见性，下一帧再移除图层和释放资源，不触发整个多视图投影栈重新烘焙。

### 6.3 图层开关显示修复

- 修复局部重绘图层的可见开关状态未及时传到视口的问题。
- 图层隐藏、显示和删除现在会同步更新运行时局部重绘源，避免面板状态与模型显示不一致。
- 增加投影图层可见性测试，覆盖图层开关与运行时渲染联动。

## 7. 合并策略与冲突处理

- 合并原则：**性能优化、局部重绘算法和拓扑/UV/烘焙服务器连接采用远端实现；贴图前端流程与 UI 采用本地实现。**
- 合并过程中主要冲突位于 `apps/web/src/routes/EditorPage.tsx`。
- 最终处理：
  - 保留本地生成面板、参考图、首次引导和底部三步局部重绘 UI；
  - 接入远端 `LiclickPerfLocalRepaintSource` 与 GPU 局部重绘状态；
  - 删除旧的手动创建局部重绘图层提示，因为远端算法会自动准备专用图层；
  - 同时保留 React `startTransition` 和本地 `useMemo` 相关逻辑。
- 对拓扑、UV、烘焙和 API 服务连接文件执行了与 `origin/master` 的差异核对，结果无差异，说明这些服务器连接沿用远端版本。

## 8. 合并后的本地热修（当前尚未提交）

最新本地测试中出现“授权成功但无法保存令牌”和“飞书身份证明无效或已过期”。定位并修复了两个问题：

### 8.1 区分交互式 Atlas 登录与服务令牌

- `atlas-cli + interactive` 现在解析为 `personal-local-component`，使用本地个人组件完成生成。
- `atlas-cli + service-token` 才解析为 `atlas-workspace`，继续走工作区传输。
- 避免把已经完成的个人飞书授权错误地送进工作区令牌保存流程。

### 8.2 修正本地身份证明校验端口

- 本地身份校验服务默认地址由旧端口 `4517` 更新为当前主服务端口 `4518`。
- 本地组件现在向 `http://127.0.0.1:4518/api/auth/local-proof/verify` 校验一次性身份证明。
- 对应修改文件：
  - `apps/server/src/services/localIdentityProofService.ts`
  - `apps/web/src/services/liclickAuthStrategy.ts`
  - `apps/web/scripts/test-liclick-auth-separation.mjs`

### 8.3 重绘效果图预览与任务关联

- 生成面板新增“重绘效果图”预览模式，与“多视图 / 单视图”并列。
- 局部生图完成后自动切换到重绘效果预览，不再自动加入单视图参考图。
- 最新局部重绘结果按项目、对象和完成时间选择；没有对象标记的旧任务只在找不到对象精确匹配时兼容回退。
- 预览、放大、下载和投射统一使用当前显示的生成结果，避免按钮仍操作上一个纹理任务。
- 为完成任务补充 `completedAt`，保证刷新或任务顺序变化后仍能选择真正最新的重绘结果。

对应修改文件：`apps/web/src/components/panels/GeneratePanel.tsx`。
