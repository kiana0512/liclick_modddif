# Li3D 优化总结（2026-08-17）

## 1. 总览

今天的优化重点围绕纹理生成稳定性、局部重绘三图工作流与数据隔离、UV 与导出一致性、新手引导交互、本地组件运行隔离、视口图层显示恢复，以及可见表面接缝修补展开。

本次整理只记录当前已经保留并生效的优化，不包含已经回退的尝试。

## 2. 纹理生成流程

### 2.1 多视图纹理任务取消

- 为同一轮多视图纹理任务增加批次标识，取消时统一识别并终止整批任务。
- 点击“取消绘制贴图”后，同时停止本地等待、轮询、后续自动投影及可以取消的远端任务。
- 取消后立即清理生成进度，不再继续停留在“纹理生成与投影”状态。
- 已取消任务返回结果时会被丢弃，避免结果继续写入图层。
- 用户主动取消不会再显示“生成贴图失败”，后端取消失败只记录到后台日志。

### 2.2 单视图与多视图后处理区分

- 单视图纹理生成完成后直接结束，不再执行“内容识别补缝”。
- 只有多视图生成并完成投影后，才会进入内容识别修补流程。
- 修正单视图与多视图完成状态、进度文案和成功提示的分支逻辑。

### 2.3 生图提示降噪

- 参考图压缩、格式转换等后台处理不再弹出黄色提示框。
- 取消任务后不再生成额外的失败提示或警告弹窗。
- 保留必要的生成进度和最终完成结果，减少重复、易误判为报错的提示。

## 3. 局部重绘

### 3.1 不同模型之间的数据隔离

- 局部重绘结果、生成记录和目标图层严格绑定当前项目与当前模型 `objectId`。
- 切换项目或模型时，自动清理上一模型的实时投影源、预览图层、蒙版和绘制工具状态。
- 新模型不再继承上一模型的局部重绘图层或局部重绘结果。
- 对旧项目中缺少模型绑定信息的历史局部重绘数据进行兼容迁移；无法确认归属的数据不会继续跨模型显示。
- 项目恢复、结果预览、局部重绘生成和图层匹配统一使用相同的模型归属判断。

### 3.2 蒙版叠加显示

- 绘制蒙版与擦除蒙版改为二值覆盖方式。
- 同一区域重复经过多个采样点时，不再累积透明度或出现深浅不同的重叠块。
- 保持已选择区域显示一致，减少连续绘制时的视觉误差。

### 3.3 局部重绘操作提示

- 删除画笔面板中“左键绘制蒙版，右键擦除蒙版”的重复提示文字。
- 工具栏仍保留必要的步骤与工具状态，不影响原有绘制、擦除、生成和应用流程。

### 3.4 ModelView INT8 三图局部重绘

- 局部重绘从原双图材质编辑链路切换到 ModelView INT8 三输入工作流 `2026.08.17-a9dbbca-flux2-klein-truev3-3input-r2`。
- 提交内容调整为三张图：当前视角白模主图、多视图材质参考图、当前视角带材质预览图。
- 白模主图继续作为几何、构图、视角和轮廓来源；多视图图负责材质与颜色分区；当前视角预览用于最终对齐和调色。
- 用户暂时无需填写局部重绘提示词，前端使用版本锁定工作流的默认提示配置。
- 蒙版不再提交至生成工作流，只保留在本地，用于生成结果返回后的绘制区域限制与回贴。
- 输出协议保持不变：接口同步返回一张最终 PNG，前端继续按单结果图保存、预览和应用。
- 前端增加轻量的当前视角颜色捕获，只执行一次颜色渲染和 GPU 读回，不重复生成蒙版、法线和深度输入。

### 3.5 三图接口与错误处理

- 客户端与工作区服务统一使用既有 `POST /api/v1/services/modelview-inpaint` 对接链路。
- 工作区服务按 multipart 字段提交 `image`、`material_image` 和 `viewport_reference`，并保持稳定幂等键。
- 三张输入图均增加格式、空文件及 50 MiB 大小校验，缺少任一必填图时返回 HTTP `422`，不会进入 GPU 队列。
- 兼容 GPU Control 结构化错误与 FastAPI 标准校验数组，界面能够显示可理解的失败原因。
- 生成结果绑定当前项目、模型、捕获记录和多视图材质参考，继续沿用现有的跨模型隔离规则。
- 服务端最终结果节点更新为 `SaveImage #32`，结果文件使用 `modelview-int8` 标识持久化。

### 3.6 2K 正方形输入与比例修复

- 当前视角白模主图固定输出为 `2048 × 2048`。
- 当前视角带材质预览图固定输出为 `2048 × 2048`。
- 多视图材质参考图保持用户原始图片尺寸，不做不必要的二次缩放。
- 修复只改正方形画布、未同步相机宽高比导致的模型横向压缩问题。
- 离屏捕获会复制当前透视或正交相机，保持相机位置、朝向和纵向取景，只根据 `1:1` 目标重新计算横向视野，因此模型比例不再拉伸。
- 本地蒙版捕获使用同一目标相机比例，确保生成结果回贴时仍与用户绘制区域对齐；蒙版本身仍不会发送至 ModelView 工作流。

## 4. UV、烘焙与模型导出

### 4.1 烘焙入口调整

- 删除进入烘焙页面前自动合并 UV 的步骤。
- 点击烘焙后直接进入烘焙页面，不再强制跳回贴图页面等待 UV 合并。
- 如果项目已经存在“合并 UV 图层”，会继续将其作为可用的 Base Color 传递；没有合并层时不再阻止页面跳转。

### 4.2 导出贴图来源修正

- 存在“合并 UV 图层”时，将 Li3D 生成的合并贴图作为导出 Base Color 的权威来源。
- 避免导出时再次叠加模型原始贴图，或错误回退到导入模型自带贴图。
- 原始贴图只在没有合并 UV 图层时作为兼容回退。
- 导出纹理图层严格限制为当前模型，避免多模型项目发生贴图串用。
- 获取项目导出数据时校验项目 ID，避免误用其他项目的最新状态。

### 4.3 远端合入的导出修复

- 修复 GLB 导出贴图方向问题。
- 增加模型导出贴图方向回归测试。
- 修复 PBR 扫光滑条参数更新后视口无响应的问题。

## 5. 图层与视口稳定性

### 5.1 UV 合成与闪屏

- 合入 UV 合成流程优化，减少重复转换、冗余边缘修复和高开销处理。
- 优化 GPU UV 烘焙、读回转换、质量混合和接缝处理链路。
- 降低图层恢复与 UV 合成过程中的视口闪烁。

### 5.2 局部重绘黑块显示

- 修复局部重绘边缘衰减和结果预览中出现黑色模块的问题。
- 优化局部重绘 Falloff Worker 与视口预览的透明区域处理。
- 增加局部重绘显示相关回归检查。

### 5.3 刷新后模型与图层恢复

- 修复刷新页面后已经生成纹理的模型重新显示为白模的问题。
- 优化项目模型恢复复用逻辑，减少不必要的模型重复加载。
- 修复所有投影图层关闭后，刷新项目再打开图层仍无法显示纹理的问题。
- 图层显隐恢复与投影视口状态保持同步。

### 5.4 可见表面接缝修补与投影缓存

- 合入可见表面补全策略，在一次 Worker 处理中补齐所有仍显示接缝标记的可写纹理像素。
- 对缺少局部有效采样源的拓扑区域增加全局颜色回退，同时严格限制在拓扑遮罩和允许写入区域内，避免跨表面污染。
- 接缝判断使用精确阈值，并保留对单像素裂缝的识别与修补能力。
- 使用物理接缝连接关系约束采样，降低相邻但不连续表面之间的颜色串染。
- 增加投影烘焙结果缓存，合并 UV 与内容识别修补可复用相同结果，减少重复烘焙和 GPU 读回。
- 缓存签名覆盖图层、模型变换、调试配置和资源版本；项目重置时会清空缓存，复用前会复制结果，避免后续合成修改缓存源数据。

### 5.5 重复操作性能

- 投影缓存命中后，内容识别修补的同会话重复执行由约 `50.98 s` 降至约 `0.415 s`。
- 4K UV 合成的同会话重复执行由约 `45.0 s` 降至约 `8.49 s`。
- 缓存仅用于项目与图层状态完全一致的重复操作，不会持久化 WebGL 深度、法线或运行时纹理，保证刷新后的资源恢复安全性。

## 6. 新手引导与对象栏

### 6.1 操作驱动的新手引导

- 新手引导改为逐步操作驱动：先显示当前步骤，用户完成对应操作后自动进入下一步。
- 不再通过点击背景、点击卡片、按 Enter 或空格直接跳过当前操作。
- 增加短暂完成确认延迟，避免状态变化时提示框瞬间跳动。
- 引导完成进度仍按项目保存。

### 6.2 取消背景模糊

- 删除新手引导的全屏黑色遮罩和背景模糊。
- 引导期间保持模型、面板和整体界面正常显示。
- 仅保留目标区域高亮边框与步骤说明卡片，并允许用户正常操作界面。

### 6.3 当前模型定位

- 对象栏为当前正在制作的模型增加明显高亮和“当前”标识。
- 切换当前模型后，对象列表会自动滚动到对应模型。
- 即使当前模型处于隐藏状态，也会保留选中高亮，便于用户定位。

## 10. 当前效果

- 多视图取消操作能够真正停止整批生成流程，不再继续等待或误报失败。
- 单视图生成路径更短，不再执行无意义的多视图补缝步骤。
- 不同模型之间的局部重绘数据完全隔离，避免残留持续污染后续模型。
- 局部重绘已使用白模、多视图材质参考和当前材质视角预览三张输入图，蒙版只在本地限制回贴区域。

- 合并 UV 贴图能够正确用于模型导出。
- 刷新、图层显隐和 UV 合成后的视口显示更加稳定。
- 接缝修补覆盖更完整，并通过投影烘焙缓存降低重复计算开销。
- 新手引导不会遮挡或模糊工作界面，并会等待用户真正完成操作。
