# ADR-0003：项目 Revision 与并发写入

- 状态：Accepted，第一步已实施
- 日期：2026-08-21

## 问题

旧保存接口使用客户端 `updatedAt` 判断新旧。客户端每次本地编辑都会更新时间，因此一个内容过期但时钟较新的页面仍可能覆盖服务器新数据；多模块并行保存时尤其危险。

## 决策

项目文档携带服务器签发的不可猜测 Revision：

- `id` 是当前保存的乐观并发令牌；
- `number` 在项目内单调递增，仅用于诊断和排序；
- `parentRevisionId` 形成保存链；
- `savedAt` 只由服务器生成。

客户端保存、重命名和移动时回传它最后读取的 Revision。令牌与当前 Revision 不同则返回 `409 PROJECT_REVISION_CONFLICT`，不得按客户端时间戳强行覆盖。Cloud 模式中，一旦项目已有 Revision，缺少令牌的写入也会被拒绝；桌面兼容模式暂时允许无令牌旧客户端，并保留原数据丢失保护。

## 迁移

1. 新项目从 Revision 1 开始；旧项目在第一次成功保存时获得 Revision。
2. 当前文件存储和未来 PostgreSQL 适配器必须遵守同一 Revision 契约。
3. 下一步把项目写入表示为版本化 Command，并把项目 Revision、资产清单和审计事件放入一个事务。
4. 在云端存储完成前，现有自动保存快照继续作为恢复机制，不冒充权威 Revision 历史。
