# ADR-0006：浏览器与对象存储直传

状态：已接受，第一阶段实现并通过本地远端部署模拟器。

## 决策

Cloud Build 的普通项目大文件不再经过 BFF 搬运。浏览器先向控制面申请短时上传意图，再使用签名 `PUT` 直接写入 S3 兼容对象存储，最后由控制面通过 `HEAD` 校验长度、MIME 与 SHA-256 后登记资产。

项目中保存的是稳定、同源且需要登录的资产地址。读取时该地址执行 ownership 校验并返回短时签名下载地址；BFF 不代理文件字节。

桌面旧上传接口在迁移期保留为 `desktop-legacy` 适配器，只有 Cloud Build 使用新协议。

## 安全边界

- 上传意图绑定用户、项目、对象键、长度、MIME、SHA-256、类别和到期时间。
- 对象键由服务端生成，用户输入不能选择桶路径。
- 完成接口可幂等重放，未通过对象存储校验的内容不得进入项目资产清单。
- 下载前重新验证当前用户的项目 ownership。
- 浏览器只获得单对象、短时、限定方法和签名请求头的 URL；长期对象存储凭据不进入浏览器。
- CORS 只允许产品 Web Origin 和签名所需的方法、请求头。

## 故障语义

- 网络错误或超时可使用同一未过期上传 URL 重试，避免重复创建对象。
- 上传成功但完成回执丢失时，可重放完成请求并得到同一资产。
- 控制面重启后，上传意图和已验证资产仍可恢复。
- 孤立的过期对象和意图由后续回收任务清理；在回收任务上线前不得把此实现标记为生产完成。

## 已知后续工作

- 当前 SHA-256 读取整个 Blob；大资产要迁移到 Worker 分块哈希，避免主线程和峰值内存压力。
- 文件魔数、图片像素、模型面数、压缩倍率和恶意内容扫描仍需在资产登记前完成。
- 文件型过渡存储只服务本地模拟；生产权威记录必须进入 PostgreSQL 事务，并与 Project Revision、Command 回执和审计事件一致提交。
