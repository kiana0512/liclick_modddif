## 2. 本轮目标

1. 消除浏览器产品对 Windows 本地组件、安装器和 `127.0.0.1:4618` 的依赖。
2. 保持贴图编辑器使用用户浏览器 CPU/GPU 完成视口、投影、图层、蒙版和交互计算。
3. 把登录、项目、Revision、账号历史、对象存储和任务编排收敛到 LI3D 应用服务器。
4. 把 Auto UV、自动拓扑、Substance Bake 和 AIGC 明确接到独立 GPU/AIGC API 集群，不用本地模拟替代正式服务。
5. 保留原产品首页、项目页、贴图工作台和工具箱的信息架构；PS/DCC 实时桥接暂缓，但不删除工具箱页面。
6. 建立可以在真实部署前重复执行的模拟部署、真实员工登录和服务纵向测试。

## 3. 关键架构变化

### 3.1 零安装 Cloud Runtime

- 删除本地组件安装器、分片下载资产、启动/停止/打包脚本。
- 删除 local-component 路由、账号绑定、身份凭据桥接和 Web 运行时门禁。
- Cloud 构建增加边界检查，禁止组件字符串、可执行文件和 loopback 回退进入产物。
- 浏览器页面直接连接同源 LI3D 应用服务器；用户无需安装 LI3D 本地进程。

### 3.2 浏览器计算平面

- 项目级 Engine Session 管理浏览器 GPU/CPU/IO lane、取消和资源释放。
- 视口、相机、蒙版、投影、图层合成、UV 图层合并、编码和边缘融合继续使用用户设备算力。
- xatlas/BVH 等浏览器实验内核只保留为回归、算法对照或未来轻量能力；不作为 Auto UV/PBR Bake 正式页面默认实现。

### 3.3 Cloud 控制面与数据面

- 新增 Release Manifest、Project Command、Project Revision 和幂等写入契约。
- 建立项目 Repository 边界，减少 Web/Server 各自直接操作文件导致的双实现。
- 大资产支持签名 URL、哈希、HEAD 校验、失败重试、幂等完成和签名下载。
- 新增 Cloud schema 目标、发布一致性检查、bundle 预算和部署模拟器。
- 账号历史从服务端按用户读取，浏览器缓存不再作为权威记录。

### 3.4 真实 GPU/AIGC 服务

- Auto UV 与拓扑读取真实 Asset V4 容量、Worker、槽位、进度、错误和产物状态。
- 模型经 LI3D 应用服务器提交独立 GPU/AIGC 集群，项目权限和用户会话不下放给 Worker。
- PBR Bake 提交真实 Substance Worker，支持 1K/2K/4K、通道选择、DirectX/OpenGL Normal、进度、取消、历史和结果下载。
- 正式模式禁止静默切到模拟器、本地 xatlas、三角简化或浏览器 BVH Bake。

## 4. 产品与 UI 保留

### 5.2 Auto UV

- Asset V4 容量：9 个 Worker、16 个槽位。
- 输入：真实 39.7 MB FBX。
- Job：`712bf6f7-198d-4f33-b73b-5e6b477fd85f`，类型 `UV_PROCESS_V2`。
- Worker：`asset-control-4090`，运行约 464 秒，进入真实账号历史。
- 结果：`UV_QA_FAILED`，严格 QA 拒绝发布，0 个不合格制品返回。
- 结论：身份、代理、上传、排队、Worker、进度、历史和失败门禁真实；生产 UV 算法质量未通过。

### 5.3 自动拓扑

- 输入：同一真实 39.7 MB FBX。
- Job：`d3258920-644b-448d-aabc-098cc1a9b18a`。
- Worker：`asset-worker-3090-b`，运行约 161 秒。
- 结果：`RETOPOLOGY_COORDINATE_MISMATCH`，低模未通过高模原始坐标门禁。
- 结论：真实服务链路和防错门禁有效；Worker 坐标恢复/输出算法未通过。

### 5.4 Substance Bake

- Worker：`asset-worker-3090-b-windows`，状态和 TLS 校验来自真实服务。
- Job：`bake_7d44660d-9585-4caf-9643-82703fdf4057`。
- 输入：`xiangzi_high.fbx`、`xiangzi_low.fbx` 与 Base Color。
- 输出：4K PNG，Base Color、Normal DX、AO、Curvature、World Normal、Thickness、Position 共七个通道。
- 页面可预览/下载，账号历史显示成功；本次纵向链路通过。

## 8. 评审与合并建议

1. 从 `codex/modernization` 创建 Merge Request，目标先选集成/测试分支，不直接合并生产 `master`。
2. 评审优先检查本地组件删除、身份/项目 ownership、真实服务边界和正式模式无 fallback。
3. 在隔离部署环境注入 Secret、生产 CA、OAuth 回调和对象存储配置；禁止把密钥写入仓库。
4. 按 P0 顺序修复 UV 与拓扑 Worker，并让机器门禁记录真实成功制品。
5. 完成生产域名、贴图回归和性能矩阵后，再评估主线合并和灰度。
