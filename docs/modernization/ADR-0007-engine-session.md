# ADR-0007：按项目持有 Engine Session

状态：已接受，第一批真实任务已接入。

## 问题

现有 WebGPU、WebGL、Worker、ImageBitmap、贴图缓存和重任务调度分别由页面或大型组件持有。跨贴图、UV、烘焙页面时，这种分散生命周期会导致任务串项目、重复探测 GPU、切页后继续占用显存、取消竞态和并发争抢视口帧预算。

## 决策

每个打开的项目获得唯一 Engine Session。会话持有浏览器计算计划、GPU/CPU/IO 任务队列、取消令牌、资源登记表、估算内存和生命周期状态。

- GPU 重任务同一会话内串行；CPU 并发使用能力协商给出的预算；IO 有独立小并发。
- 同 key 的新任务默认取消旧任务，并在真正执行回调前再次检查取消信号。
- 销毁会话时先取消并等待活动任务清理，再按逆序释放 Worker、GPU、ImageBitmap 和缓存资源。
- 页面短暂切换采用十秒释放宽限；贴图到 UV 的同项目导航复用同一会话，不重新探测设备。
- Cloud 能力不足只改变本地计划，不允许把普通计算切到服务器。
- 浏览器根节点暴露会话 ID、项目 ID、状态、任务数和资源字节数，供部署 E2E 与内存回归读取。

## 第一批接入

编辑器的全分辨率 UV 合并和内容识别修补已从全局重任务队列迁到项目 Engine Session 的 GPU lane；会话尚未可用时保留原调度器作为迁移期兼容路径。

自动化测试覆盖 CPU 并发上限、同 key 替换、取消竞态、活动任务先于资源释放、资源逆序释放和幂等销毁。远端部署浏览器测试证明同一项目从贴图切到 UV 后 Engine Session ID 保持不变。

- 将 UV、PBR Bake 和拓扑的产品工作流迁入本地 lane；当前页面上的远端服务仍是未通过状态。
